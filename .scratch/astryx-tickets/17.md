## Parent

Part of #40

## What to build

处理对话内和列表中的 Approval，管理现有审批规则。

范围限于 Web UI，遵循父 spec 与 ADR 0001；保留业务/API/权限语义。每票包含实现和行为验证，不另拆测试票。

## Acceptance criteria

- [ ] 覆盖对话审批卡片、全局列表、Bot 规则及管理端审批/指导入口。
- [ ] 同意、拒绝及其他现有操作发送正确请求，避免重复决定；失败反馈与重试保持原行为。
- [ ] 批准与实际执行结果分开显示，不能把用户同意展示为执行成功。
- [ ] Standing Rule 等选项只在原本允许的场景提供，不扩大持续许可范围。
- [ ] 验证允许/拒绝/权限不足、过期或已处理等现有状态，键盘与焦点可完成决定。
- [ ] 对本票改动运行相关行为测试、Web 类型检查及生产构建，记录实际结果；不以组件内部 DOM 或生成类名作为断言。
