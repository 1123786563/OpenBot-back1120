## What to build

创建和打开 Conversation，发送内容并阅读流式回复。

范围限于 Web UI，遵循父 spec 与 ADR 0001；保留业务/API/权限语义。每票包含实现和行为验证，不另拆测试票。

## Acceptance criteria

- [ ] 覆盖单人/群组现有创建和打开入口，Conversation 与 Thread 路由关联保持。
- [ ] 发送、附件、模型选择、输入法、听写和语音入口维持已有能力与限制。
- [ ] 流式回复、取消/错误/重试等现有状态正确，滚动和继续输入不受迁移破坏。
- [ ] 保留现有消息渲染及专用实现，统一基础控件与外围样式。
- [ ] 验证发送至流式结束的完整用户流程及失败路径，检查明暗、窄屏、键盘和长内容。
- [ ] 所有常规页面票完成后再开始，遵守已确认的迁移顺序。
- [ ] 对本票改动运行相关行为测试、Web 类型检查及生产构建，记录实际结果；不以组件内部 DOM 或生成类名作为断言。
