## What to build

OpenObserve 自动按两类数据分别过期清理，管理员可查询保留期内数据；副本过期不影响 PostgreSQL 和 Activity 中的原有审计记录。

沿用父规格及 ADR 0006：保留 Opik、Activity 和 PostgreSQL 审计权威记录；仅平台管理员查询，不上传凭据或正文。告警、定制仪表盘及桌面/CLI 自动采集不在范围内。

## Acceptance criteria

- [ ] 运行日志保留 30 天、审计副本保留 90 天，明确实际时间判定依据和清理执行周期；生产配置可复现。
- [ ] 在隔离测试环境采用可控时间或缩短等价策略周期，验证过期记录实际从查询中消失，未到期记录仍可查；不能仅检查配置值。
- [ ] 验证两类数据策略独立：运行日志过期不会提前删除尚未到期的审计副本，反之亦然。
- [ ] 审计副本过期后，同一原始审计事件仍遵循 PostgreSQL 原有保留规则，并可在规则允许期间通过 Activity 查询。
- [ ] 重启服务后策略仍生效，新日志继续遵循对应保留策略，管理员访问限制保持。
- [ ] 测试使用隔离数据，不删除真实业务审计记录；生产 30/90 天配置与缩短周期的行为测试均提供证据。
- [ ] 记录保留策略、查询时间范围和清理延迟说明，明确历史不回灌及日志副本可能存在缺口。

## Blocking rationale

依赖任务 1（接入当前业务系统运行日志，统一到 OpenObserve 查询）提供已验证的运行日志端到端部署与查询链路。
依赖任务 2（接入审计日志副本，保留 Activity 与 PostgreSQL 权威记录）提供已验证的审计副本端到端链路。
