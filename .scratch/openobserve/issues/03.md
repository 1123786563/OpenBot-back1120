## Parent

Part of #82

## What to build

管理员使用同一 Run ID 在 OpenObserve 和保留的 Opik 中定位同一次 Bot 运行，无需复制 Agent 正文或新增跳转页面。

沿用父规格及 ADR 0006：保留 Opik、Activity 和 PostgreSQL 审计权威记录；仅平台管理员查询，不上传凭据或正文。告警、定制仪表盘及桌面/CLI 自动采集不在范围内。

## Acceptance criteria

- [ ] 执行真实 Bot Run，在 OpenObserve 服务运行日志和 Opik 中找到同一次运行，记录可复现查询步骤与标识映射。
- [ ] 同一 Run 的适用日志保持稳定关联；至少运行两个独立 Run，验证不会串到另一运行。
- [ ] 已有请求 ID 与 Run ID 可同时保留，不将请求 ID 默认视为 Run ID；明确边界处标识如何传播或映射。
- [ ] 验证没有 Run 的启动或基础服务日志仍可查询，且不会被填入伪造 Run ID。
- [ ] Opik 原有 Agent 轨迹与模型调用观测继续工作；OpenObserve 不因关联而上传模型输入输出或其他正文。
- [ ] 无需自动跳转 UI 即可完成关联验收；文档说明人工查询方法。
- [ ] 使用真实 Harness/服务接口验证；缺少标识传播能力时明确并完成上游修改，不能以手填样例标识宣称完成。

## Blocking rationale

依赖任务 1（接入当前业务系统运行日志，统一到 OpenObserve 查询）提供已验证的运行日志端到端部署与查询链路。
