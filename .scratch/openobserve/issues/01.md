## What to build

盘点并记录当前服务端日志系统，将现有正常运行、业务处理、警告和错误日志接入自托管 OpenObserve。平台管理员可使用统一入口排障，不能仅接入示例错误或审计日志。

沿用父规格及 ADR 0006：保留 Opik、Activity 和 PostgreSQL 审计权威记录；仅平台管理员查询，不上传凭据或正文。告警、定制仪表盘及桌面/CLI 自动采集不在范围内。

## Acceptance criteria

- [ ] 形成现有服务端日志清单：逐项记录服务、日志用途、输出方式、现有启用级别、采集路径及覆盖状态；区分业务运行日志、审计日志和 Opik 轨迹。
- [ ] 部署可复现的自托管 OpenObserve 与采集链路，记录固定版本、启动配置、存储位置、凭据配置方式及查询步骤；重启后已入库且未过期的数据仍可查询。
- [ ] 清单内首期服务端运行日志全部覆盖；逐来源触发实际日志并提供查询证据。未接入来源必须明确列为未完成项及原因，不能静默遗漏后宣称整票完成。
- [ ] 对正常业务操作、现有 Info/等价级别、Warn/等价级别与 Error/等价级别分别验证入库；保留现有启用级别，不强制开启 Debug，不丢弃正常业务日志。
- [ ] 查询结果包含必要的时间、服务、环境、级别和经筛选的事件/错误信息；已有请求 ID 和 Run ID 保留，无 Run 的系统日志不伪造关联 ID。
- [ ] 上传前采用必要字段过滤并去除凭据；使用合成敏感标记验证对话正文、模型输入输出、工具参数/返回正文，以及嵌套字段和异常信息中的这些内容均不出现在实际上传载荷和查询结果中。
- [ ] 管理员可访问查询 UI/API，普通用户和未认证请求被拒绝；写入凭据受控且不暴露给普通用户。
- [ ] 接入仅收集新日志，不扫描上传已有历史日志；验证一个接入前标记不入库、接入后标记可查。桌面端和 CLI 日志不自动上传。
- [ ] 采集与发送不引入业务同步依赖，提供有限缓存/重试的基础配置；完整故障压力验收由后续故障票覆盖。
- [ ] 提供从真实服务操作到 OpenObserve 查询结果的可重复验证入口和证据，不能仅通过配置文本断言；若发布镜像能力不足，明确上游依赖，不以模拟源代替真实服务验收。
