## What to build

当 OpenObserve 不可用时，运行日志和审计副本使用有限缓存与重试，业务及权威审计继续正常工作；恢复后新日志正常入库。

沿用父规格及 ADR 0006：保留 Opik、Activity 和 PostgreSQL 审计权威记录；仅平台管理员查询，不上传凭据或正文。告警、定制仪表盘及桌面/CLI 自动采集不在范围内。

## Acceptance criteria

- [ ] 两条采集链路均有明确且可配置的缓存容量、重试次数/时限、退避和耗尽处理，记录实际采用值及资源边界。
- [ ] 停止或断开 OpenObserve，持续执行业务操作和产生日志；请求仍能成功，PostgreSQL 审计持续写入且 Activity 可查询。
- [ ] 故障持续至缓存/重试上限被实际触发，验证允许丢弃副本而不会无限增长内存、磁盘或重试任务；提供负载、持续时间和资源观测证据。
- [ ] 验证运行日志与审计导出均无业务同步等待依赖；对比正常与故障期间请求结果，记录观察到的延迟，不能只断言进程仍存活。
- [ ] 恢复 OpenObserve 后，新运行日志和审计副本均继续入库，无需业务服务人工重启；不要求已丢弃副本补齐。
- [ ] 故障和恢复期间不回灌历史数据，不绕过脱敏或访问权限，不改变 PostgreSQL 权威记录。
- [ ] 提供可重复的断连、耗尽、恢复端到端测试步骤及结果；说明查询可能存在缺口，不承诺恰好一次或无损导出。

## Blocking rationale

依赖任务 1（接入当前业务系统运行日志，统一到 OpenObserve 查询）提供已验证的运行日志端到端部署与查询链路。
依赖任务 2（接入审计日志副本，保留 Activity 与 PostgreSQL 权威记录）提供已验证的审计副本端到端链路。
