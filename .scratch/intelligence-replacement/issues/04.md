# T04: 辅助模型调用的授权与积分闭环

## Parent

Part of #83 — https://github.com/1123786563/OpenBot/issues/83

## What to build

一次用户触发的辅助模型操作通过 Bifrost 完成授权、积分预留、执行和结算，并可查看结果。

## Acceptance criteria

- [ ] 通过真实后端公开边界演示辅助操作，关联付款人、Bot、原始工作与消费上限，逐次校验后才调用 Bifrost。
- [ ] 使用测试凭据与测试积分验证并发预留不超支、重复结算不重复扣费、无付款人不启动收费步骤。
- [ ] 绕过服务端授权、直接访问供应商或使用网关凭据跳过积分预留均被拒绝。
- [ ] 请求超时或断流时查询状态、保留结算确认状态，不盲目重发；遵循既有 24 小时预留与迟到成本规则。
- [ ] 禁用模型、余额不足、网关不可用时有可见失败/暂停状态，不自动切换模型或绕过网关。
- [ ] 核实底层 SDK 自动重试与新服务内部模型调用的可控性；不能控制的组合不开放付费流量。
- [ ] 若现有网关或账本尚不可用，记录明确外部阻塞，不以 mock 测试代替此闭环验收，也不扩张为未授权账本重建。
- [ ] 提供用户可观察行为的测试或演示证据，遵守父规格及既有 ADR；不得把静态分析或模拟测试当作真实服务验收。

## Blocked by

- T01 — 核实后端源码与可运行基线：其交付是本票所用链路的前置条件。

## Completion gate

仅当上述验收全部满足、阻塞票已完成且外部前置条件已验证时才可完成。遇到源码、账本或第三方能力缺口须明确报告阻塞，不静默降级要求。
