## Parent

Part of #83 — https://github.com/1123786563/OpenBot/issues/83

## What to build

平台查看一次真实 Run 的元数据追踪，Opik 故障不影响用户对话。

## Acceptance criteria

- [ ] 自托管 Opik 接收实际 Run 的标识、模型、耗时、用量、状态和评分字段，平台可查询归属。
- [ ] 默认没有提示词、回答、工具结果、录制或凭据正文；检查实际上传载荷与存储结果。
- [ ] 普通用户不能绕过 OpenBot 访问内部平台凭据或其他用户追踪，管理界面限定平台人员。
- [ ] Opik 停机时普通对话继续，补传队列有明确容量，恢复后可安全补传。
- [ ] 补传最多等待 24 小时；时间或容量超限记录缺失数量并告警，不无限增长。
- [ ] 元数据默认保留 30 天且可配置，实际验证到期清理不影响对话、Memory 或账本。
- [ ] 提供用户可观察行为的测试或演示证据，遵守父规格及既有 ADR；不得把静态分析或模拟测试当作真实服务验收。

## Completion gate

仅当上述验收全部满足、阻塞票已完成且外部前置条件已验证时才可完成。遇到源码、账本或第三方能力缺口须明确报告阻塞，不静默降级要求。
