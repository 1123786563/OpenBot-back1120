# T16: 全部受支持客户端适配与契约验收

## Parent

Part of #83 — https://github.com/1123786563/OpenBot/issues/83

## What to build

Web、手机、桌面及录制端等已确认支持面均完成新链路，保留各自已有用户能力。

## Acceptance criteria

- [ ] 依据票 01 的支持面清单逐一记录适用场景，不能用单个 Web 演示代表所有客户端。
- [ ] 各支持面对话、身份、历史、实时续接、审批、取消和错误提示均通过对应行为验收；非适用项写明依据。
- [ ] Memory、学习审核、版本管理、录制和删除功能在原有支持面保持可用，不通过隐藏入口满足替换。
- [ ] 桌面连接云端 SaaS，不再需要本地 Intelligence；录制端使用 OpenBot 上传与确认协议。
- [ ] 真实第二设备、旧连接凭证过期、离线恢复和重复事件不串空间、不重复答案或动作。
- [ ] 复用公开契约测试，记录协议变化与客户端兼容性；至少一次真实服务联调，不以全部 mock 通过为完成。
- [ ] 提供用户可观察行为的测试或演示证据，遵守父规格及既有 ADR；不得把静态分析或模拟测试当作真实服务验收。

## Completion gate

仅当上述验收全部满足、阻塞票已完成且外部前置条件已验证时才可完成。遇到源码、账本或第三方能力缺口须明确报告阻塞，不静默降级要求。
