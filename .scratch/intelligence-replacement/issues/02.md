# T02: 持久化一段 Conversation 并恢复历史

## Parent

Part of #83 — https://github.com/1123786563/OpenBot/issues/83

## What to build

用户在测试客户端完成对话，重启 OpenBot 后仍能读取消息、Bot 归属和历史。

## Acceptance criteria

- [ ] 从公开接口与实际客户端创建 Conversation、发送消息、显示回答，持久化 Thread、消息与 Run 关联。
- [ ] 重启后读取相同历史；重复提交不会产生重复消息，失败不会显示虚假成功。
- [ ] 两名个人空间用户无法读取或修改对方 Conversation、Thread 和消息；服务端强制检查身份。
- [ ] 此链路在无 Intelligence 服务和凭据的环境运行，不以 Opik 作为恢复依据。
- [ ] 通过现有 Harness 对话契约验证实际模型收到完整获准历史和正确 Bot Role。
- [ ] 确定并记录本切片所需持久化方案、公开契约与兼容策略；提供可重复运行的演示与行为测试。
- [ ] 提供用户可观察行为的测试或演示证据，遵守父规格及既有 ADR；不得把静态分析或模拟测试当作真实服务验收。

## Blocked by

- T01 — 核实后端源码与可运行基线：其交付是本票所用链路的前置条件。

## Completion gate

仅当上述验收全部满足、阻塞票已完成且外部前置条件已验证时才可完成。遇到源码、账本或第三方能力缺口须明确报告阻塞，不静默降级要求。
