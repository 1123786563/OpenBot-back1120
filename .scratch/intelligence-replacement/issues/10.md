# T10: 技能发布、版本选择与冲突保护

## Parent

Part of #83 — https://github.com/1123786563/OpenBot/issues/83

## What to build

获批提案发布后供后续 Run 使用，用户能固定版本、跟随更新和回退。

## Acceptance criteria

- [ ] 新增、更新、移除提案批准后实际改变对应技能交付；通过真实 Harness 观察模型所见目录与内容。
- [ ] 每次 Run 固定启动版本，发布后只有后续 Run 使用新版本；固定版本、跟随与回退均有可操作入口。
- [ ] 学习不能扩大工具权限；即使固定旧版本，当前权限撤销和技能停用仍阻止后续相关使用。
- [ ] 提案之后用户修改同一技能时旧提案失效，按既有预算重新分析而不覆盖用户修改。
- [ ] 批准与发布状态分离，发布失败显示已批准未发布并保留旧有效版本。
- [ ] 并发发布、重启及安全重试不重复创建版本；失败恢复不会交付部分技能内容。
- [ ] 提供用户可观察行为的测试或演示证据，遵守父规格及既有 ADR；不得把静态分析或模拟测试当作真实服务验收。

## Blocked by

- T03 — Run 实时恢复、审批与取消：其交付是本票所用链路的前置条件。
- T09 — 手动学习形成可审核提案：其交付是本票所用链路的前置条件。

## Completion gate

仅当上述验收全部满足、阻塞票已完成且外部前置条件已验证时才可完成。遇到源码、账本或第三方能力缺口须明确报告阻塞，不静默降级要求。
