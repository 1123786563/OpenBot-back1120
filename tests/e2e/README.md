# OpenBot Web 浏览器测试

安装依赖后，执行 `bunx --no-install e2e-web install chromium`。运行 `bun run test:e2e` 可访问已启动的 OpenBot，默认地址为 `http://localhost:3010`，也可通过 `OPENBOT_WEB_URL` 指定。用 `bash scripts/test-web-e2e.sh` 可以启动独立的 App 和 Server。该脚本需要 `DATABASE_URL` 指向可迁移的临时 pgvector 数据库。

| 套件 | 行为 | 执行方式 |
| --- | --- | --- |
| `guest` | 访客跳转登录页，验证 Casdoor、Google 和公司 SSO 的发起与回跳参数 | 默认运行，所有 PR 都执行 |
| `navigation` | 旧链接跳转、Bot 创建、收件人选择、首页路由、草稿、附件上传与移除 | 所有 PR 均在隔离的本地单用户环境执行 |
| `personal` | 个人版技能自动授权、学习审核与功能入口 | 所有 PR 均在独立的个人版单用户环境执行 |
| `authenticated` | Casdoor 登录、Bot 创建和取消、刷新后保留 Bot、固定流式回复和消息持久化 | 受信任 PR 或手动执行 |
| `live` | 用真实模型生成非空回复，并确认刷新后仍可读取 | 手动执行 |

登录套件使用测试 Casdoor 实例和专用账号。为该实例登记 `http://localhost:3010/api/auth/callback/casdoor`，用临时数据库运行，并按 [工作流](../../.github/workflows/web-e2e.yml) 配置账号、OAuth 和 Intelligence 的变量与凭据。将 `OPENBOT_E2E_AUTHENTICATED` 设为 `true` 后，仓库内分支的 PR 会运行登录套件。

访客套件通过固定的身份提供商响应检查 Casdoor 仅自动启动一次、失败后允许手动重试、错误回跳停留在登录页，以及 Google 和公司 SSO 等待用户操作。代码核对实际 POST 的回跳地址和公司邮箱。两种版本均验证已登录用户以文档导航访问验证端点，原样携带数字、布尔、JSON 和含空格的流程 ID，省略流程 ID 则进入首页。流程 ID 的编码与长度限制继续由 `bun:test` 覆盖。

两种版本的桌面回跳测试使用生产组件，记录分派到操作系统的 `openbot://open` 请求。确认接口返回成功或失败前都不分派，响应后只分派一次，手动链接始终可用。模拟 Tauri 环境时从真实回跳路由进入对应 Gmail 账户页。团队版的登出测试覆盖两种错误响应格式，浏览器核对错误提示、当前会话和重试成功后的登录页。

聊天中的私密登录使用固定流式事件触发真实前端工具。测试延迟私密请求的创建，核对后台标签页先显示等待，创建后出现可打开的私密表单，并测量表单的实际布局。独立登录路由覆盖先发用户名和密码、收到验证码要求后切换表单、输错验证码后重试。代码逐次核对 POST 路径及请求体，验证码提交仅发送验证码。

应用目录使用固定供应商响应和 Chromium 的真实标签页。个人版添加 Slack、GitHub 或 Gmail 后打开授权标签页，提交测试授权后，目录轮询并更新连接状态。需要密钥的 PostHog 在原标签页打开密钥表单，刷新时恢复普通详情页。团队版添加应用仍在目录，账号保持未连接，用户可另外发起连接。另覆盖目录按凭据类型排序、密钥说明、Arcade 的动作分类和权限范围、等待供应商识别、供应商不匹配的回跳、设置读取失败，以及并发添加时仍显示先前请求的错误。

应用详情和单 Bot 授权页验证正常动作仍可访问，跳过的动作显示为状态提示。团队版保留供应商原始动作名，个人版显示易读名称。管理端核对两种供应商各自的部署密钥提示，以及仅支持共享账号的应用在两种状态下可执行的操作。

General 设置通过实际路由验证姓名和长期指令的编辑、提交和刷新后回显。模拟 Desktop 外壳验证三种 AI 连接的摘要、凭据不显示、修改连接后的停止状态，以及隐私说明、切换请求、环境强制关闭和旧版 IPC 的缺省行为。This computer 页用 Chromium 的真实轮询验证后台下载、就绪和正在安装的状态，也覆盖已是最新版、检查失败、旧版外壳、不自动更新的构建、服务说明和打开日志目录时的 IPC 参数。 This computer 还检查运行与停止两种状态的页面文案和可访问名称，以及 Copy diagnostics 写入剪贴板的版本、底层工具和服务标识。

Notifications 校验每种更新独立保存渠道，暂不可用的渠道保留原选择。管理员、自托管用户、普通成员和 Desktop 分别显示适用的设置说明。设备移除后仍保留投递日志，日志显示投递状态以及对应的失败原因。Check-ins 验证用户设置和管理员限制同时反映在通知页和单 Bot 页面。GitHub 仓库事件验证 Webhook 地址、提交请求和刷新后的仓库记录。侧栏通过 Chromium 键盘事件验证俄文、希腊文及不同拉丁字母键位，并核对展开状态。

团队版 Memory 从旧设置链接进入实际 Capabilities 页面，检查学习事实的 Bot 署名、每条事实的开关及刷新后的保存状态。添加失败时展开并核对服务端错误，重新打开对话框后断言旧草稿和错误已清除，再次提交并验证刷新后仍能读取新事实。

Setup 通过实际设置路由验证管理员和本地用户能访问，普通成员返回 General 且浏览器没有读取检查清单。覆盖首次加载、失败恢复、手动重检、待修复数量的读屏名称、必需和可选状态的颜色、键盘焦点及凭据页跳转。两种版本的许可提示和导航文案由生产服务端代码生成。收到成员版清单时，浏览器验证中性文案和隐藏修复详情。

团队管理端的审批测试核对成员计算机命令上限、团队规则的请求和刷新后回显。自然语言审批规则和审核指导使用固定模型响应，检查读取解释、修改后的重新校验、历史决策回放、预计模型调用数及保存请求。触发回放和保存的操作分别断言。Setup 摘要、审批回放文案和审核指导的 Audit 文案继续由 `bun:test` 覆盖。

个人审批设置在团队版和个人版验证规则的保存、失败后保留草稿及重试、实际请求、刷新后的状态、已移除 Bot 的规则，以及长作用域和易读动作名称。团队版还核对被强制执行的自动审核、锁定的团队规则和共享账号请求权限。共享账号审批显示当前与拟议范围，成功后移出列表，遇到其他管理员已处理的请求则可展开服务端错误。聊天接管用例验证已完成的浏览器步骤继续可见，待处理卡片只对应一个工具调用，确认自己已完成后只提交一次 `handled`。

审批的动作名称和可选决定通过真实聊天、Bot 的 Needs you 区域和 OpenMuse 的 Needs you 弹窗验证。文件保存、App 工具和网站操作显示可读名称，网页内部引用只保留在数据中。由 Check-in 发起的任务只提供单次允许和拒绝，普通审批仍可设置长期许可。文件夹规则显示实际文件夹与 Bot 名称，对已经撤销的文件夹或已移除的 Bot 显示说明。

Bot 所有者可从详情页请求共享账号审批。浏览器检查只发送一次请求，刷新后仍显示等待提示。管理员看到发布 Bot 时同步授予共享账号访问的说明。单 Bot 授权页按当前共享范围预填，取消时不写入，缩小到仅所有者并关闭外部输入后，断言授权请求和刷新后的开关状态。

团队版 Connections 验证逐动作授权由部署能力控制，列表按权限与状态排序，搜索可找到默认隐藏的动作。授权确认在发出请求前解释影响范围，随后进入固定的供应商同意页。个人账号和共享账号的回跳即使晚收到权限数据，也能高亮对应动作，刷新后清除。共享账号只允许管理员发起授权，打开账号页时不会发出个人连接确认。团队管理端切换共享模式前预览受影响的账号和 Bot，撤销失败后保留弹窗和服务端说明，重试成功后刷新仍为共享模式。缺少部署配置的 App 从连接列表隐藏，直接访问时展示可读状态。两种版本验证连接、授权和身份绑定的回跳提示单独或同时到达时均只显示一次。

两种版本用 Chromium 验证连接密钥表单。打开表单时显示供应商的字段说明和密钥指引，密钥输入始终遮蔽。提交被拒时保留本次输入以便重试，关闭后页面仍显示拒绝原因。重新打开会清空草稿，并等待供应商更新字段。测试检查新字段的默认值、供应商拒绝读取字段时的提示、实际提交的字段，以及连接回跳仅打开一次表单。重新检查被供应商拒绝后，页面立即更新，刷新后仍显示失败结果并允许重试。没有安全动作可尝试时保留上一条检查结论。成功的检查更新日期，断开后清除旧结果，连接新密钥后显示尚未检查。如果供应商拒绝密钥但已保留账号，页面给出失败原因和断开入口。读取连接列表失败时，页面显示错误并隐藏连接操作，团队管理页仍可刷新工具和切换 App 状态。刷新恢复后重新展示已记录的账号状态。

Gmail 多账号测试以实际账号名称定位操作。浏览器验证新增账号完成供应商同意后回到连接页、默认账号刷新后保留、断开仅影响所选账号。两种版本验证未完成的 OAuth 同意、供应商返回意外字段、部署缺失密钥和供应商重连能力。Desktop 的 Chromium 模拟检查会在窗口重新获得焦点时补做一次确认。密钥提交成功或失败后，代码检查客户端缓存中没有测试密钥，并验证断开连接后其他读取者也不再得到旧检查结果。探测结果与服务端定义的对应关系继续由 `bun:test` 检查。

团队管理端的 App 和工具详情区分目录暂时读取失败与目录中确实没有对应 App。团队版和个人版的 Connections 也验证目录读取失败时显示对应错误，并隐藏连接操作。

供应商更新密钥字段时，Chromium 验证新默认值、未编辑字段的更新和用户已输入值的保留，并核对请求中的字段名及值。表单测试验证标签、帮助、必填、遮蔽和默认值，字段清单与服务端定义的对应关系由 `bun:test` 检查。

聊天连接卡从固定的工具拒绝回放进入。测试检查授权请求返回前已打开空白标签页，供应商页面不替换原对话，弹窗被阻止时仍可打开授权链接。供应商要求输入密钥、拒绝请求或记录已有连接时，空白标签页会关闭。已撤销凭据和共享账号不会被识别为当前人的连接。授权完成后，代码检查原 Thread 只发送一次接续消息并收到固定流式回复。状态读取失败后重新挂载的卡片显示「Continue」，保持挂载的卡片会自动接续一次。

个人版从真实聊天页面验证一次点击即可启用 Notion 并发起授权。Chromium 请求进入应用的真实 App 路由，使用临时 PostgreSQL 和固定的 Notion 注册响应，分别覆盖 App 关闭和已启用但尚无工具的状态。浏览器弹窗和 Desktop 外部链接脚本都验证实际授权地址、OAuth 参数及登录前无工具授权。Gmail 场景覆盖启用前已知登录方式和启用后才发现登录方式，断言等待授权响应时按钮显示进度，最终只交接一次且仍停留在原对话。

团队版聊天权限卡回放验证按拒绝中指明的 Bot 查询权限，较旧的拒绝使用当前对话的 Bot。浏览器检查个人账号连接、共享账号缺失或失效、共享范围未获批准、App 未启用和 Bot 未获授权时的提示与操作。账号后来重新连接时清除过期的重连入口，普通工具结果不会生成权限卡。App 在最新任务中变为可用时，只发送一次接续消息并收到固定流式回复。较早的任务不自动接续。打开对话时已就绪的 App 只为此前受阻的任务提供「Continue」，刷新后不会重复发送。

团队版权限操作分别验证启用 App、授予 Bot 和连接共享账号所需的访问请求。测试核对实际请求只携带 Bot 和 App，提交与撤回后刷新仍保持结果，焦点随按钮切换。请求被拒时可以展开「Details」查看服务端说明并重试。管理员可一次授权或打开对应设置页。Bot 所有者需先连接时，只有授权回跳后才会提交授予请求，成功后原对话只接续一次。

聊天中连接密钥 App 或重新连接 Composio、Arcade App 时，浏览器验证跳到正确的 Connections 页面。部署自己的 OAuth 重新连接会在新标签页打开授权。关闭授权页后可以在原对话再次连接。如果授权页仍打开但模拟的浏览器句柄报告已关闭，等待提示保留到原对话重新获得焦点。个人版还验证 App 已开启但尚未获授权时的一键连接，以及缺少供应商密钥时的设置入口。权限提示文案的纯函数用例继续由 `bun:test` 覆盖。

管理员的 Providers 页面验证模型来源名称、实际供应商标识、允许列表为空时的提示、默认模型的限制说明，以及搜索、添加完整模型名、取消和保存。测试核对实际提交的模型名并在刷新后检查保存状态。Permissions 验证组织开关的请求和刷新后的状态，旧 Enterprise 地址进入管理首页。个人版旧管理地址返回 Settings，实际对话提供测试供应商返回的全部模型。App 详情还覆盖所有者授权在共享账号、个人账号及仅管理员可授权时的说明。

管理端访问请求的 Chromium 用例核对 App 详情按 App 筛选，列表顶部也显示尚未开启 App 的请求。审批和驳回后刷新仍保留结果，计数随之更新。审批遭拒时可在对应请求展开服务端说明并重试。Boundaries 用例覆盖模板和自定义规则、取消和确认删除、规则预览中的 App 与计算机动作，以及读取或编译失败。删除用例返回列表核对保存结果。

Boundaries 的文字生成场景使用固定的模型接口响应，检查规则内容、编译说明、自动预览和手工修改提示。重复生成时保留管理员自填的说明，改写已有规则时保留名称。测试核对点按 Add 或 Save 后才提交规则和原始描述，并通过刷新检查保存结果。编译失败、仅描述允许行为、缺少模型密钥分别检查对应的界面反馈和写入限制。

Computers 的网络白名单用例复用服务端录制的模型响应，验证生成模式、域名列表和近期访问预览。手工改动后，界面保留原始解读并重新预览新列表。测试在窄视口测量说明文字宽度和对话框滚动，核对保存的策略在刷新后仍然可见，并检查原样保存会保留域名端口且跳过预览。

Permissions 的文字生成用例使用固定模型响应和服务端权限计算，验证受影响人员、保留权限的群组和近期使用记录。移除一项变更后，预览只接收剩余的变更。确认保存后，测试核对批量请求包含原始描述，并在刷新后逐一检查三个群组的授权。Audit 文案与预览摘要的纯函数用例继续由 `bun:test` 覆盖。

管理端 Check-ins 验证各 Bot 的发现项被人启动的比例、跳过原因和空统计，核对组织开关写入及每日上限的整数和边界校验。保存后刷新，开关与上限仍显示更新后的值。

个人 Skills、Admin Skills 和编辑页直达链接均覆盖首次列表读取失败。列表已确认为空时，模拟网络恢复触发后台重试，测试核对接口确实返回 500，并检查页面继续显示已知的空列表。

管理端 Automatic learning 验证活动和隐藏 Bot 的参与设置、默认容器和暂停状态，以及容器自动分配、不可用时的提示与允许创建时的保存结果。设置读取失败时，参与与审批各区块都显示服务端详情。审批设置与参与草稿分别保存，测试核对两个请求并刷新验证结果，也覆盖审批保存失败时对话框保留选择。

管理端 Learning 审核用例检查容器及个人提案的技能正文、附加文件和对话证据，以及批准、拒绝和失败后重试。共享请求须先读到技能才能审核，请求发生版本冲突时，测试核对重试提交最新版本。运行用例覆盖手动触发、状态刷新、失败说明、已发布技能和有无后端仪表盘的界面差异。运行轮询间隔继续由 `bun:test` 检查。

团队版 Settings → Learning 覆盖三种技能共享模式、管理员关闭共享时的限制、技能详情和读取或保存失败。测试核对开关与共享请求的写入顺序、刷新后的状态，以及已申请技能不会重复提交请求。个人版使用独立部署配置，验证技能仍可打开，页面只提供阅读操作。
