# 官方验签与账单格式夹具（#70）

本目录的夹具内容取自支付宝官方公开文档，供 `official-fixtures.test.ts`
使用。每个夹具在此注明来源、版本与预期结果；官方样例中的签名值由支付宝
平台私钥生成（平台私钥不可获得、也不可出现在仓库中），因此向量测试的做
法是：**保留官方样例的逐字节待验签串**，用每次运行新生成的 RSA-2048
“支付宝侧”测试密钥按官方规则重签后，经生产验签代码核验——规则与串均
来自官方文档原文，密钥是临时的，不含任何生产密钥。

## 1. 异步通知验签样例（async-notify-sample.md）

- 来源：支付宝开放平台文档中心《自行实现验签》
  <https://opendocs.alipay.com/common/02mse7>（Markdown 源
  <https://opendocs.alipay.com/common/02mse7.md>）
- 文档页脚更新时间：`2026-03-26 16:54:27`（抓取于 2026-11-19）
- 官方规则（原文要点）：
  1. 除去 `sign`、`sign_type` 两个参数外，通知返回的参数皆是待验签参数；
  2. 剩余参数 url_decode 后按字典序排序，组成 `k=v&k=v` 待签名字符串；
  3. `sign` base64 解码为字节串；
  4. 用支付宝公钥做 RSA（RSA2 = SHA256WithRSA）验签。
- 文档给出的完整通知示例与官方待验签串均逐字保留在
  `async-notify-sample.md` 中。
- 预期结果：该待验签串按官方规则重签后，生产 `verifyAlipayNotification`
  返回 true；任一参数被篡改（金额翻转）返回 false。

## 2. 同步返回验签样例（sync-response-sample.md）

- 来源：同上《自行实现验签》“同步返回验签 · 公钥模式”一节。
- 官方规则（原文要点）：
  1. 只对返回 JSON 中 `xxx_response` 的值验签；
  2. 待验签内容需包含首尾的 `{`、`}`，双引号也参与验签；
  3. 正斜杠按响应原样（`\/` 转义形态）参与验签；
  4. SHA256WithRSA（RSA2），签名取平级 `sign` 成员（base64）。
- 文档给出的 `alipay.trade.precreate_response` 样例与待验签字段逐字保留。
- 预期结果：按原始字节（含 `\/` 转义与官方排版）重签后，生产
  `verifyAlipayResponse` 返回 true；把响应 JSON 重新序列化（改变空白/转
  义）后验签必然失败——证明生产代码从不重新序列化后验签。

## 3. 交易明细账单夹具（2088102119685838_交易明细_20260101.csv）

- 来源：商家中心（b.alipay.com）账单下载的“交易明细列表”公开格式：
  `#` 注释头、表头列 `支付宝交易号 / 商户订单号 / 业务发生时间 / 收/支 /
  金额(元) / 退款批次号`、GBK 编码、CRLF 行尾、末尾 `#流水总数` 汇总行。
- 说明：该格式的**逐字节官方样本**随商家中心实名账号下载，属真实商户闭
  环（#72）核对项；本目录的夹具为**脱敏重构**（号码、时间、金额均为编
  造），格式形态与上列字段集按公开资料对齐。
- 预期结果：GBK 解码成功；解析出 2 行（1 收入 2.00=200 分、1 支出
  0.50=50 分带退款批次号）；删除任一必需列或放入非 Exact 金额整体失败。
- 商户号 `2088102119685838` 取自官方《自行实现验签》文档示例中的
  seller_id，仅作格式说明用途，非本仓库配置的商户。
