客户提交 Asia/Shanghai 后返回 timezone=null、applicable_timezone=UTC，目标时区验收未通过。所查源码 Customers::CreateService 与 Organizations::UpdateService 的时区赋值均受 Premium 检查限制，不能绕过。

用户已选择保持社区版：OpenBot 管理北京时间周期，Lago 保持 UTC。事件级归集替代路径已完成下述隔离验证，时区配置的许可限制不再阻断此架构；生产对账器和账本集成仍未实现，不能将 Lago 月度账单直接当成用户周期。

设计详见 [时区映射](billing-timezone-mapping.md)。本地日历样例验证闰年、普通年、大小月、跨年及原始日号恢复；来源批次样例验证边界后结算仍引用旧周期积分、剩余预留过期。这些是设计样例，不是生产并发账本测试。

真实 Lago v1.57.0、Premium=false 的 API 场景通过，见 [实测摘要](evidence/lago-timezone/summary.json) 与 [复用脚本](../../scripts/verify-lago-timezone.py)：

| 场景 | 实测结果 |
| --- | --- |
| 北京时间 2024-01-31 至 02-29 | UTC 窗口 01-30 16:00 至 02-28 16:00，原用量 5 微积分 |
| 北京时间 02-29 至 03-31 | UTC 窗口 02-28 16:00 至 03-30 16:00，用量 23 微积分 |

## 实现前需完成的技术验证

- 固定实际部署版本和镜像摘要，复核与本地源码差异；无许可时完整 API 调用链可用。
- 事件接收、异步处理与查询缓存分别观察，能够发现已接收但未聚合的事件。
- 已验证历史整秒事件与月末边界归集；仍需生产适配层验证亚秒时间保真、并发补传、分页移动、断点恢复及调整幂等，不重写历史时间。
- 核实整数微积分端到端无精度损失、合理最大值及超界拒绝；Lago 用量汇总不代替 OpenBot 对价格与舍入的独立测试。
- 已定位历史后端基线 `6d1919a3b53a0730894258f197f3beb4e8db4f2f` 的准入、后台 runner、模型配置和工具 callback 候选点；当前运行镜像仍缺匹配源码/构建证明。历史候选点不是当前生产钩子验收，详见 [实施计划](billing-implementation-plan.md)。

## 后续验收：并发补传与亚秒精度

已在独立 Lago v1.57.0 社区版 PostgreSQL 环境执行 [运行脚本](../../scripts/verify-lago-concurrency.py)，证据见 [摘要](evidence/lago-concurrency/summary.json)、[API 响应](evidence/lago-concurrency/api-responses.json) 和 [数据库只读精度核查](evidence/lago-concurrency/database-precision.json)。测试环境已清理。

- 通过：第一页后插入历史事件，复现 page_30 重复、inserted_35 漏读；完整重扫和 ID 去重恢复精确 5 条预期记录及用量。
- 通过：8 个同时发送的请求构成 4 对重复 ID，每对一个 200、一个 422，最终仅新增 4 条；不得把所有 422 当作成功，适配层仍需核对错误码和原内容。
- 微秒存储及过滤通过：±1 微秒、±1 毫秒边界在数据库及查询中保留；端点仍为双端包含。
- 原 timestamp 响应精度不通过：GET/list 序列化为毫秒，边界和边界后 1 微秒显示相同。已验证替代路径：上报原始整数 properties.occurrence_us，扩大查询范围后按整数半开区间过滤，准确选中 1 微秒窗口内唯一事件。
- 不包含：持续压测、ClickHouse、生产对账器持久化水位与无限并发写入下的收敛保证。生产以本地已持久化事件集合为核对依据，不以重复扫描总数相同判定完成。

## 后续验收：调整幂等与跨周期账本参考模型

本仓库未找到生产账本源代码，后端仍通过发布镜像提供。以下验证使用独立临时 SQLite 数据库、独立连接及真实事务/唯一约束；它是可执行设计参考，不是生产后端验收。脚本见 [verify-billing-ledger.py](../../scripts/verify-billing-ledger.py)，结果见 [摘要](evidence/billing-ledger/summary.json)。

| 场景 | 模型结果 |
| --- | --- |
| 跨周期多批次 | 旧周期 100、积分包 100，边界前预留 150，边界后消费 120：旧周期扣 100、积分包扣 20、积分包剩 80 |
| 并发重复结算 | 16 次重试仅提交一次、一个待同步记录；不同金额报冲突 |
| 提交前故障 | 结算或调整写入后、提交前注入异常，账本和待同步记录一起回滚；重试成功 |
| 调整幂等 | 16 次并发仅一条 +17 调整与一条待同步记录；重新打开数据库后重试不新增；同键不同周期/金额拒绝 |
| 竞争消费 | 剩余 80 时两个并发预留各 60，仅一个成功 |
| 过期余量 | 旧积分 100、预留 80、跨界消费 60，最终消费 60、过期 40、可用 0，下一步不能消费过期余量 |
| 24 小时释放与迟到结算 | 释放后迟到成本归平台；到期同时释放和结算仅一个结算记录、可用余额不减少；提前释放拒绝 |

模型未验证生产 PostgreSQL 隔离级别、账户授权、运行消费上限、服务进程强制退出及真实 outbox 投递。只有生产实现接入后通过同等行为测试，才可关闭相应上线验收项。

## OpenBot 实现后验收

- 并发预留、账户余额及运行上限原子检查，无负可用余额、无重复扣分；子代理共用上限。
- 本地账本结算与待同步记录可靠提交；同步重试、乱序、重启及断网不丢不重。Lago 不可用不影响可靠的本地消费。
- 用量未知满 24 小时释放后，迟到结果归平台承担；不能再次追扣。
- 月末、闰年、北京时间边界、提前续费、过期重购及跨周期步骤结算符合设计。
- 退款冻结与并发消费互斥；结果未知不解冻，确认失败后解冻仍遵守积分到期规则。
- 渠道通知验签、订单金额币种及商户身份匹配、重复及乱序通知、主动查单、30 分钟关单竞争、迟到付款处理。
- 微信和支付宝各自验证付款、退款、退款未知与账单对账；测试环境通过不等于真实商户产品已开通。
- 支付确认后发放权益只执行一次，崩溃可恢复；不让 Lago 的付款状态或核算账单触发二次发放。
- 日对账区分资源消耗、用户扣分、平台承担、用户自付与人民币收退款；调整可追溯且不修改历史流水。
- 付费主体权限、自带密钥费用归属、任务转移授权、订阅降级及历史任务不补跑。
- 用户账单来自 OpenBot，显示预留、结算确认中、退款处理中及补偿来源；敏感内容不进入 Lago。
