# Intelligence 替换设计

状态：整体方案已于 2026-11-17 获用户确认，作为后续技术验证、实施和验收的正式依据；[ADR 0005](../adr/0005-replace-intelligence.md) 为 accepted。未开始实现或运行验证。

## 已确认

- 彻底解除 CopilotKit Intelligence 依赖，保留现有产品能力。
- 使用 Hindsight 和 Opik 作为替换方案的组成部分；职责已确认，具体接入方式待技术验证。
- 完整替换包括 Intelligence 当前承载的其他职责，不能仅替换记忆和评估后保留其余依赖。
- Hindsight 和 Opik 均自托管，作为云端 SaaS 内部服务统一运维。用户通过 OpenBot 使用功能，平台人员使用 Opik 管理界面。
- 优先取得可修改的后端源码；无法取得时再单独确认后端重建范围。尚未授权直接重建完整后端。

## 现状与约束

现有架构文档将持久化 Thread、运行事件与回放、实时 gateway、Memory 和 Automatic Learning 等能力关联到 Intelligence。保留的 API 路径还涉及 trajectories、analytics、trust-policies、usage 等；路径清单不是已验证的功能实现清单。依据：`docs/architecture.md`、`api/intelligence-reserved.yaml`。

当前仓库通过预构建镜像引入后端，尚未取得可修改的完整后端源码。源码获取路线已确认，具体源码位置仍待确定。

沿用现有 ADR 的边界：Casdoor 管理身份，OpenBot 管理业务授权；Corsair 承接外部连接，OpenBot 保留动作审批和审计；OpenBot 积分账本是结算权威；平台密钥模型调用经过 Bifrost，辅助调用也需满足归属、预算和逐次预留约束。

Memory 继续遵守根术语表的审核与可见范围要求，Automatic Learning 继续形成技能变更提案。Hindsight 的记忆推理与 Opik 的评估不能直接视作已经实现技能提案、审核和发布。

## 已确认的职责分工

| 职责 | 承担方 |
| --- | --- |
| Thread、消息、Run 状态和事件的权威记录 | OpenBot 后端与持久化数据库 |
| 实时订阅、断线补发、运行事件回放 | OpenBot 服务端，基于持久化事件 |
| 记忆内容、检索和基于记忆的推理 | Hindsight；OpenBot 强制审核、隔离和删除规则 |
| 运行追踪、质量评估和反馈分析 | Opik；不作为会话恢复或积分结算依据 |
| 学习材料、Insight、Learning Proposal、审核与技能发布 | OpenBot 组织完整流程，按需使用 Hindsight 与 Opik |
| 操作录制与文件材料 | OpenBot 管理访问权限和生命周期，保存于适当的文件存储 |

以上职责分工已由用户确认。

## 已确认的产品行为（Q5–Q10）

- OpenBot 保存记忆原文、版本、来源、审核与可见范围，是权威记录；Hindsight 保存可重建的检索与推理副本。未接受、暂停、遗忘或当前 Bot 无权读取的记忆不能进入召回及推理上下文，不允许生成答案后才过滤。
- Hindsight 故障不阻断普通对话，OpenBot 对已接受且有权读取的记忆提供基础检索，修改排队同步；高级记忆推理明确提示不可用。暂停和遗忘立即在 OpenBot 生效，不等待外部同步。
- Opik 故障不阻断普通对话；追踪在有限队列内等待补传，评估暂停。补传期限与超限处理见 Q11–Q16；队列容量待技术验证。
- 刷新、断线、换设备后恢复已保存的消息与进度；服务崩溃后仅在可证明安全的检查点续跑。外部动作结果不明时标记待确认，不自动重做。此规则不改变既有身份停用后由用户手动恢复任务的要求，也不授权自动重试收费模型调用。
- 自动学习开启后自动分析并生成提案，默认由用户批准后才改变技能；用户可以主动开启自动批准，范围仅限自己的学习空间。新增、修改、删除技能均保留证据和版本，技能变化不能扩大工具授权。
- Opik 默认仅保存运行标识、模型、耗时、用量、状态及评分；正文只在明确选择的评估或排障范围内上传，样本脱敏并设置保留期限。默认无法在 Opik 查看完整正文。
- 不迁移旧 Intelligence 的对话、记忆、录制和学习记录，以新部署验收完整能力。旧数据保持原状，清理另行处理；本次不授权删除旧数据。

## 已确认的执行规则（Q11–Q16）

- 可安全重复的数据同步自动重试；可能已产生模型费用的请求先查状态，不盲目重发，无法确认则标记待处理。旧版本同步不能覆盖新的编辑、暂停或遗忘。无法保证 Hindsight 副本符合当前权限时，降级为本地检索。
- 保留手动 Learn now。定时学习由用户明确开启并选择材料范围与预算；开启后默认每天分析一次新增的已完成对话和已提交录制，无新材料不运行，频率可调整。
- 暂停学习后不再启动新的分析或收费步骤；已经发出的请求只收尾记账，不自动发布技能。余额不足暂停，充值后由用户明确恢复，不补跑积压的定时任务。
- 用户主动开启的学习或评估沿用积分规则。平台排障与回归评估由平台承担，不扣用户积分；使用正文仍需遵守样本选择和脱敏规则。
- 每次 Run 固定启动时使用的技能版本；新发布版本只影响后续 Run。保留固定版本、跟随新版本及回退能力，权限撤销和技能停用立即阻止后续相关使用。
- Opik 元数据默认保留 30 天，明确选中的正文样本默认保留 7 天，均可配置并到期自动清理。追踪补传队列最多等待 24 小时，超限记录缺失数量并告警，容量参数待技术验证。这些期限只适用于观测副本，不影响对话、记忆、录制、学习证据及计费审计记录的生命周期。
- 完全替换必须在 Intelligence 服务、凭据与许可证全部缺席的环境验收，覆盖全部受支持客户端的对话、断线恢复、审批、取消、记忆审核和隔离、学习提案和技能发布、录制上传、外部依赖故障降级，以及 Bifrost 调用归属和积分约束。允许更换旧协议，但必须保留用户可见能力。

## 已确认的数据与发布规则（Q17–Q21）

- 对话、有效记忆、已提交录制、学习提案和技能版本默认持续保存，用户明确删除或配置保留策略后才清理；订阅到期不删除。备份期限与存储配额上线前确定，空间不足明确提示，不静默丢弃材料。
- 删除对话或录制前展示关联成果；默认保留已独立接受的记忆和已发布技能，用户可选择一并清理。未完成分析停止，未批准提案失效，证据正文及副本进入清理流程；保留成果标记来源已删除。
- 只有完整上传并经服务端确认的录制才自动进入学习。中断后保留待上传状态，支持续传和去重，停止录制不代表上传完成。无法补齐时允许用户明确提交已有片段，标记材料不完整。
- 提案生成后若对应技能已被修改，旧提案失效并重新分析，不自动覆盖；自动批准也遵守此规则，重新分析沿用消费授权和预算约束。批准与发布分别记录，发布失败保留原有效版本，安全重试不能重复创建版本，界面显示已批准但未发布。
- 数据库、文件存储、实时协议、Hindsight 隔离方式、队列容量和备份参数留待取得后端源码后验证。技术实现必须满足已确认的产品与验收规则，无法满足时提出取舍，不自行降低要求；全部通过前不切换正式服务。

## 实现前验证与交付顺序

1. 取得可修改的后端源码，核实 Intelligence 实际调用、数据模型、恢复机制与许可门禁；无法取得则另行确认重建范围。
2. 验证 Hindsight 权限隔离、审核与撤销、副本同步和降级，以及 Hindsight/Opik 内部模型调用经过 Bifrost 和积分授权的可行性。
3. 确定持久化、文件、实时与后台任务实现，补齐对话恢复、录制、学习发布和观测生命周期。
4. 在没有 Intelligence 服务、凭据和许可证的新环境完成各客户端及故障场景验收，通过后再切换正式服务。

上述顺序不代表接入已实现。删除传播与备份清理的实现、容量及备份参数需在上线前验证并记录；旧数据不在迁移或清理范围。整体方案已确认，技术验证须遵循本文规则；无法满足时提出取舍，不自行降低要求。

## 契约核查发现

- 实时恢复须覆盖刷新、多端查看运行、断线续接与去重、取消和历史补齐；现有客户端契约不能证明任意 Run 可在服务端崩溃后自动续跑。依据：`api/asyncapi.yaml`、`api/openapi/conversations.yaml`。
- 录制器当前直接向 Intelligence gateway 上传，替换须覆盖客户端上传、确认与重传、序号去重、结束后的排空状态。依据：`docs/design/data-flows.md`。
- 自动学习包含分析调度、证据、技能版本与发布交付；新个人 SaaS 默认审核规则已由 Q5–Q10 确认，取代旧个人/团队版默认分支。依据：`docs/automatic-learning.md`。
- 现有记忆文档承诺依赖不可用时本地读写降级、恢复后补同步；新方案已确认保留基础检索降级。Hindsight 推理必须在读取前满足可见范围，不能仅在生成答案后过滤。
- 单 agent 单 thread、旧 thread 命名和 Phoenix 协议属于可替换的实现选择；产品归属、隔离及所有客户端行为是验收对象。

上述规则是目标设计，尚未通过新后端运行验证。
