# Casdoor 统一身份：面向个人用户的三端 SaaS

## Problem Statement

OpenBot 需要面向公众提供个人 SaaS。用户应能自助注册，从 Web、手机端、桌面端进入同一个独立工作空间，而不必依赖企业邮箱域名或管理员手动建号。当前企业 SSO、桌面免登录本地模式和组织初始化流程不能直接满足这一体验；账户停用与身份服务故障也必须同时约束访问和后台执行。

## Solution

使用 Casdoor 统一用户身份和登录，OpenBot 保留应用会话与业务权限管理。用户验证邮箱后首次进入时自动获得独立 Personal Workspace（个人工作空间），其 Bot、Conversation（对话）、Connection（个人应用连接）和 Computer（Bot 工作计算机）与其他用户隔离。三个客户端连接同一云端服务。

停用账户后一分钟内阻断访问并停止后台执行；无法确认账户状态超过一分钟时采取相同暂停策略。恢复后用户可重新访问，但已停止的任务和计算机只能手动恢复。

## User Stories

1. 作为新用户，我希望通过 Casdoor 自助注册，以便无需管理员审批即可使用服务。
2. 作为新用户，我希望验证邮箱后才进入 OpenBot，以便确认联系方式属于我。
3. 作为首次登录的用户，我希望自动获得个人工作空间，以便直接开始使用。
4. 作为并发打开多个客户端的用户，我希望只创建一个用户和空间，以免数据分散。
5. 作为初始化失败的用户，我希望重试后能进入原定空间，以免出现重复或残缺账户。
6. 作为 Web 用户，我希望通过统一登录入口访问自己的空间，以便无需选择企业身份提供方。
7. 作为手机用户，我希望登录同一账户，以便访问已有 Bot 和对话。
8. 作为桌面用户，我希望连接云端同一空间，以免默认创建独立本地部署。
9. 作为个人空间所有者，我希望管理自己的空间，以便控制自己的 Bot 和连接。
10. 作为普通用户，我希望平台管理权限与个人空间管理权分离，以免错误获得其他用户的管理能力。
11. 作为用户，我希望其他用户无法读取或修改我的 Bot、对话和文件，以便保持数据私密。
12. 作为用户，我希望连接凭据和浏览器登录状态不被其他用户使用，以便保护外部账户。
13. 作为用户，我希望自己的 Bot 计算机与其他用户隔离，以免执行过程泄露数据。
14. 作为用户，我希望修改并重新验证邮箱后保留账户和空间，以免失去已有数据。
15. 作为用户，我希望普通退出仅影响当前客户端，以便其他设备仍能继续使用。
16. 作为用户，我希望退出登录不停止云端任务，以便任务继续运行。
17. 作为用户，我希望能退出所有设备，以便撤销所有 OpenBot 登录会话。
18. 作为管理员，我希望在 Casdoor 停用账户后一分内阻断其所有客户端访问，以便停用及时生效。
19. 作为管理员，我希望停用同时停止该用户后台任务和计算机，以免撤销访问后仍持续执行。
20. 作为用户，我希望停用期间保留数据，以便恢复后继续使用。
21. 作为运营者，我希望身份状态超过一分钟无法确认时暂停访问与执行，以便通知丢失或身份服务故障不绕过停用要求。
22. 作为用户，我希望恢复身份服务后不自动重启已停止任务，以免意外触发外部操作。
23. 作为用户，我希望恢复后自行重启任务和计算机，以便控制何时继续执行。
24. 作为平台管理员，我希望也通过 Casdoor 登录，以便所有人员使用统一身份入口。
25. 作为运维人员，我希望有经过演练的服务器恢复流程，以便 Casdoor 故障时恢复服务而无需公开备用密码入口。
26. 作为维护者，我希望三端使用同一身份关联规则，以便邮箱变化和多端登录不会产生重复账户。

## Implementation Decisions

- 以已接受的 Casdoor 身份 ADR 为依据；优先复用现有 OIDC 接口，兼容性不作未经验证的承诺。
- Casdoor 管理身份和统一登录，OpenBot 管理应用会话及业务权限。普通用户和管理员都通过 Casdoor；关闭其他普通登录入口和免登录模式。
- 公开注册，邮箱验证后获得 OpenBot 访问资格。无需邀请、白名单或人工审批。
- 每个新用户映射一个专属组织作为个人工作空间；对平台是普通用户，对自己的空间是所有者。重复登录不新增空间，初始化需支持并发及失败重试。
- 邮箱为可变联系方式，不作为账户归属的唯一依据。稳定身份关联必须通过实际 OIDC 行为验证；不以邮箱相同自动合并不同身份。
- 首期没有团队邀请；不同用户的数据、文件、连接凭据、浏览器状态和计算机隔离。同一用户的 Bot 可以共享其自己的计算机。
- 桌面端连接云端 SaaS，不再默认启动本地独立服务。Web、手机端和桌面端访问同一用户与空间；客户端不得持有服务端 OIDC secret。
- 普通退出撤销当前客户端会话；全部设备退出撤销全部 OpenBot 会话。退出不停止云端任务。
- Casdoor 停用后一分钟内阻断客户端访问并停止该用户全部后台执行和计算机，保留数据。仅撤销 Casdoor 令牌不足以证明要求达成。
- 账户状态超过一分钟无法确认时暂停访问与执行，接受身份服务故障影响可用性。恢复且状态验证通过后只恢复访问资格，已停止任务与计算机由用户手动恢复。
- 不直接用现有 SCIM 停用实现临时暂停：其文档描述了邮箱禁用及连接凭据撤销，不能假定满足数据保留和稳定身份要求。
- 管理员没有公开备用密码入口，通过服务器运维恢复身份服务，并在上线前演练。
- 实施顺序为后端入口确认、OIDC 登录验证、用户与空间初始化、状态与执行控制、三端接入、完整隔离与恢复验收。具体数据库结构和新增 API 尚未核实，不预设已存在。

## Testing Decisions

- 用户已确认以“真实 Casdoor → OpenBot 服务端 → 三端用户行为”为主要测试边界，优先复用现有公开 API 和客户端流程。测试可观察结果，不断言内部函数调用、表布局或实现顺序。
- 在独立测试数据和固定版本服务上执行，覆盖身份登录、空间初始化、会话管理、后台执行控制、计算机隔离及三端客户端。
- 现有 Web 组织测试使用真实组件、查询缓存和模拟 API；移动端组织测试验证账户切换后的请求作用域；认证客户端测试可补充错误和退出行为。这些测试不能代替真实服务端隔离验证。
- 使用两个无关用户，验证直接构造他人组织或资源请求仍被拒绝；同时检查文件、外部连接、浏览器状态和计算机隔离，而非只检查 UI 是否隐藏。
- 验证邮箱未验证无法进入、公开邮箱注册、三端同一身份、邮箱变更、并发首次登录及初始化失败重试。
- 验证当前端退出不影响其他设备、全部设备退出令旧会话失效，两者均不停止云端任务。
- 从 Casdoor 停用成功开始计时，验证一分钟内访问阻断、任务停止和计算机停止；不能只断言通知已收到。
- 丢弃通知、断开身份服务连接，验证从最后一次成功确认账户状态起超过一分钟即暂停访问与执行，包含无前台请求但任务仍在运行的情况。
- 恢复账户和身份服务，验证数据保留、访问恢复、任务及计算机不自动重启，并可由用户手动恢复。
- 验证平台权限与个人空间所有权分离、其他登录入口不可绕过、管理员运维恢复可执行。

## Out of Scope

- 历史用户与数据迁移；这不授权删除现有环境数据。
- 团队空间邀请与多人协作准入。
- 用户自助永久注销及数据永久删除流程。
- Casdoor 接管 OpenBot 业务权限、Bot Grant 或审批规则。
- 桌面本地独立服务作为本次目标模式。
- 订阅、支付、积分及其他并行产品改造。

## Further Notes

**实施阻碍：尚缺可修改的 OpenBot 服务端源码或经过验证的扩展接口。** 本地 checkout 和已检查的公开上游均未发现认证后端源码；本地服务端镜像仅发现编译程序与数据库迁移。发布流水线复用后端发布镜像。不能以修改前端或增加网关作为已满足后台停止和租户隔离的证明。

本地 Casdoor 的 OIDC 发现端点读取成功，声明 S256 PKCE 和后端退出通知能力，但尚未验证真实授权码登录及端到端停用。已有企业 OIDC 注册依赖管理员会话、组织及邮箱域名；公开注册入口和管理员启动仍需后端验证。

按 to-spec 工作流使用 `ready-for-agent` 标签，表示规格已确认，不代表后端依赖已经解除。后续执行者应先解决服务端入口阻碍，不得将方案核查描述成已经完成对接。
