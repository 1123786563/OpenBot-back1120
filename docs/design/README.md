## 证据如何理解

- **实现**：可在当前仓库函数和调用关系中直接核对的行为。
- **契约**：OpenAPI、AsyncAPI 或共享类型规定的行为；服务端是否正确执行，仍需运行验证。
- **说明**：代码注释记录的原因；与实现不一致时保留差异，不把注释当成已执行的行为。

每篇文档均链接到证据源。没有后端源码的状态转换、数据库事务、权限执行顺序和队列细节，不从前端反推成实现结论；这里也不根据结果补写历史 ADR。

## 已发现的差异及核验范围

1. 现有 [Architecture](../architecture.md) 的固定组织 ID 描述已补充为当前组织选择逻辑：多组织、个人版和旧部署走不同分支，见 [组织边界](permissions.md#组织边界)。本地前端实现可核验，部署端的组织隔离需服务端验证。
2. [tool-steps.ts](../../shared/tool-steps.ts) 注释规定计算机动作串行且首错后停止；LangGraph 的 [execute_tools](../../agent-langgraph-agui/src/tool_runtime.py) 本地循环能证明串行，但循环自身没有首错后中止判断。回调服务是否拒绝后续动作，无法从此循环证明。本文只把串行记录为可确认实现，首错中止列为待端到端核验。
3. 当前仓库没有 `server/`、`agent-computer/`、`supervisor/` 源码目录；[Compose](../../docker-compose.yml) 使用发布镜像。已有文档和注释中出现这些源码路径，不能视为本工作区可直接打开的实现证据。

## 维护

改领域名称时更新术语表；改行为时更新对应设计页和用户文档；改 API 时先改其源文件。优先维护已有 [用户文档](../README.md)，本目录保留跨模块关系和证据，避免再复制完整配置与操作指南。
