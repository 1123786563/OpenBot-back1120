# Bifrost 模型调用网关

状态：整体设计已获用户确认，ADR 0004 已接受；具体校验实现、账本接口、Bifrost 版本与首批兼容组合保留为技术验证项，接入尚未实现或验证。

## 已确认

- Bifrost 用作 Agent 调用模型的统一出口。
- 首要目标是统一模型接入与供应商切换，同时考虑密钥集中管理。
- 会话、任务调度和工具执行继续由 OpenBot 管理。
- OpenBot 管理的 API 密钥模型调用统一经过 Bifrost，覆盖 Bot 对话、路由判断和后台任务；现有 Claude / ChatGPT 订阅登录路径暂不迁移。
- 首期只使用平台持有的供应商密钥，由网关集中管理；Harness 仅获得受限的网关访问凭据，不开放用户自带供应商密钥。
- 供应商和模型由管理员显式配置、切换；首期不做自动故障切换，请求失败不会自动改用另一种模型。
- 管理员维护可用供应商、模型清单和默认模型；用户可在获准的模型清单中选择。
- 网关访问凭据按租户隔离；模型调用关联用户、Bot 和 Run，供应商密钥仍由平台集中持有。
- Bifrost 使用自托管开源版，作为独立服务部署，由 OpenBot 运维管理；模型入口仅供受控服务访问，管理界面仅向运维开放。
- OpenBot 负责消费积分余额、扣费和余额不足时停止调用；Bifrost 提供模型用量数据与额外限额，网关预算不能替代积分约束。
- 主动工作由发起用户支付，后台工作由所属用户支付；委派沿用原付款人，无法确定付款人时不启动收费调用。具体授权及账户转移遵循现有计费设计。
- 每次模型请求前预留积分并限制成本上限，完成后按实际用量结算并释放余量；并发请求不能重复使用已预留积分。
- 每次 Run 固定启动时选定的供应商和模型，默认配置变更只影响新 Run；管理员明确停用模型后阻止后续模型请求并说明原因。
- 网关默认只记录归属、模型、耗时、状态、用量和费用等元数据，不保存提示词、工具内容或模型回答正文。临时正文排障的范围及保留期限另行确定。
- 每次模型调用必须经过服务端校验付款人、模型及有效积分预留，完成预留后才允许 Bifrost 转发。租户访问凭据不能绕过校验；无法覆盖内部模型调用及重试的 Harness 暂不开放平台付费模型。
- Bifrost 不可用时停止新模型请求并提示服务暂不可用，不绕过网关直连供应商。可能已被接收的请求进入结算确认流程，不自动重发。
- 按“模型 × Harness”的兼容性验证结果开放可选模型。验证包括流式响应、工具调用、取消、用量返回及所需协议；多模态和推理参数等能力通过验证后才开放。
- 路由等辅助调用可由管理员单独配置模型，但必须有服务端执行记录，关联付款人和原始工作，并受原始工作的消费上限约束。
- 首期关闭 SDK 和网关自动重试，由用户明确重试。每次重试形成独立调用并重新预留积分，旧调用独立结算。
- 先用测试凭据及测试积分完成端到端验证，再逐步开放付费流量。必须验证不可绕过预留、并发不超支、重复通知不重复扣费、断流可对账、跨租户访问被拒绝以及网关日志无正文。后端或账本接口不具备时不开放真实扣费。

## 与计费设计对齐

[计费设计](billing.md) 已确认：预留时锁定单价；Run 与委派、子代理共享消费上限；用量不明时预留最多保留 24 小时，之后释放且迟到成本由平台承担；不自动重发可能已成功的收费调用。这些已有规则直接沿用，不另建网关扣费规则。

计费设计中的自带模型账户免 token 积分规则不构成本次新增自带 API 密钥支持；现有订阅登录路径仍不迁移。

当前仓库使用预构建后端镜像，未找到可修改、验证的完整积分账本实现。上述规则是目标设计，尚不能据此宣称已经具备逐次调用预留与结算能力。

## 技术验证阶段待选定

- 凭据签发、轮换及撤销机制，调用归属的可信传递方式。
- 每次调用的预留强制校验位置（网关扩展或内部代理）和用量对账接口。
- 可修改后端与账本接口的获取方式、Bifrost 版本及首批验证的模型与 Harness 组合。
- 元数据保留期限、部署容量和运维参数；临时正文排障未获默认启用授权。
