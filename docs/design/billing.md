# 订阅、消费积分与支付设计

产品规则与职责边界已完成逐轮确认，本文为设计基线；功能尚未实现，技术可行性以运行验收结果为准。具体商业参数在上线前另行确定。

源码定位、分阶段交付及阻塞项见 [生产计费实施计划](billing-implementation-plan.md)。

## 已确认规则

- 对接 Lago，微信支付和支付宝用于主动付款购买及续费，首期不提供免密自动扣款。
- 个人账户独立计费，不共享组织余额。采用预付费积分，可用积分不足时停止消费，不产生消费欠款。
- 首期提供月付订阅套餐及额外积分包；套餐权益与积分余额分别定义。
- 套餐积分仅当期有效、不结转；积分包长期有效。消费优先扣即将到期的积分。
- 订阅过期后停止订阅专属权益，仍可消费积分包使用基础按量服务。
- 首次购买及过期后再次购买，在服务端确认支付成功并实际开通权益时生效，按生效日起算一个月，避免确认延迟侵占周期。有效期内提前续费接在当前周期之后，下个周期开始才发放下一期积分。
- 所有使用平台付费资源的执行均计费，包括主动对话、定时任务、Goal、Check-in 和子代理。单纯浏览历史或管理设置不扣积分。

## 系统职责与核算

职责边界与每日对账见 [ADR 0003](../adr/0003-openbot-ledger-lago-billing.md)，技术证据见 [Lago 接口映射](lago-interface-mapping.md)。

用户周期由 OpenBot 按北京时间计算，Lago 社区版保持 UTC。两者通过原始事件 ID 与发生时间对账，不能直接等同月度总数；月末、跨周期及迟到调整见 [时区映射](billing-timezone-mapping.md)。

- 本地账本及记录可靠时 Lago 故障不阻断消费，恢复后补传；无法可靠保存记录则停止新增消费。
- 积分与人民币分开核对，不产生二次应收。每个消费账户建立独立、持续的计量关系，用户账单以 OpenBot 记录为准，Lago 原始账单仅用于运营核算。
- 首期验证 Lago 零金额计量，汇总原始资源用量及已结算积分，不独立复算逐步积分价格；人民币收款由 OpenBot 记录。
- 迟到用量按原发生时间形成原周期核算调整，不覆盖历史账单；若 Lago 不支持调整，由 OpenBot 对账记录承接。
- 平台故障、重复执行及超过 24 小时才确认的消耗单独记为平台承担，自带密钥用量也区分费用归属；不将资源用量与用户扣分的差额一律认定为漏扣。
- 积分以整数微积分同步，1 积分等于 1,000,000 微积分。它是内部计量单位，不是另一种商品或货币。
- 资源用量与积分结算分别上报，以步骤 ID 关联。调整追加新记录并引用原记录；重试保持事件 ID 不变，同 ID 内容不一致时报警。
- Lago 仅保存核算必需的账户 ID、步骤 ID、资源类型、用量、费用归属及时间；不保存对话正文、提示词、模型输出或支付密钥。

## 已确认的消费与套餐变更规则

- 按实际资源用量计价；不同模型分别配置输入、输出、缓存 token 的积分单价，其他收费工具按次数或时长配置。用户可查看明细；调价只影响后续消费，历史保留原计价依据。具体价格待定。
- 用户取消或任务未达目标，已实际发生的有效资源消耗仍扣费；OpenBot 自身故障造成的无效消耗或重复执行由平台承担，失败原因及扣费结果需可追溯。
- 执行前预留积分，按步骤结算实际消费并释放余量。并发任务不可重复使用已预留积分；不能覆盖下一步时暂停，不启动新的收费调用。无法约束成本上限的调用首期不开放；充值后由用户明确恢复暂停任务。
- 主动请求扣发起人积分；定时任务、Goal、Check-in 扣创建者积分；子代理及委派工作继承原始工作的付费账户。外部事件无明确付费账户时不启动收费执行。
- 当前周期套餐不变，更换套餐下一周期生效；当期积分不足购买积分包。已提前购买的下一周期套餐不直接替换，需先处理原订单。

## 已确认的支付、退款与结算规则

- 自有微信支付和支付宝商户号直连，人民币收款；统一网页收银台支持套餐购买、续费和积分包购买。电脑扫码，手机采用商户已开通的移动支付方式，桌面客户端打开网页付款。
- 服务端核实支付成功后才发放权益，同笔付款只发放一次。尚未确认时展示“支付确认中”，通过主动查询及对账补齐漏通知。
- 首期人工审核退款：未使用积分包、未开始续费周期可申请全额退款；已消费积分包和已开始订阅不提供常规自助退款。平台故障与重复收款单独处理。
- 退款审核时冻结对应剩余额度或待生效权益；渠道退款成功后撤销，失败后解除冻结。
- 跨周期时，已开始收费步骤使用原预留积分结算；后续步骤只能使用仍有效的积分。释放的旧周期套餐积分直接过期；不能预留整个长任务的积分以绕过到期规则。
- 积分精度为六位小数，按单个收费步骤汇总用量后四舍五入，不按 token 或流式片段分别取整；展示避免将微小消费误示为免费。

## 已确认的购买资格与边界规则

- 从未订阅或已过期的用户均可购买积分包并使用基础按量服务。
- 基础用户可使用对话、定时任务、Goal、Check-in；订阅主要增加周期积分、并发数和自动任务名额。具体额度及价格待定。
- 订阅到期保留数据和配置；超过基础额度的自动任务暂停，由用户选择保留启用的任务，不直接删除。
- 订阅周期采用北京时间，保留原始购买日为月度锚点，缺少该日期的月份取月末，后续恢复原锚点；每天的生效时间点保持一致。此处购买日指服务端确认并实际开通权益的生效日。
- 订单有效期为 30 分钟，过期先向渠道确认并关闭。迟到通知若实际付款发生在有效期内，正常履约；若实际付款发生在订单失效后，进入异常退款处理。重复通知不重复履约。
- 最多提前购买一个周期；已购下一周期套餐换档，先完成原续费订单退款，再购买新套餐。退款处理中禁止重复购买同一周期。
- 平台故障补偿恢复原扣减来源；已过期的套餐积分改为补发到账后 30 天有效的补偿积分。补偿关联原消费明细，仍优先消费即将到期积分。

## 已确认的异常恢复与商业配置规则

- 无法可靠查询或预留积分时不启动新的收费步骤；已开始步骤保留用量，恢复后补结算。仍允许查看历史和管理任务，明确提示计费服务暂不可用，不误报余额不足。
- 超时且实际用量不明的步骤进入“结算确认中”，预留最多保留 24 小时；无法确认则释放，后续确认的成本由平台承担，不再追扣用户。不自动重发可能已成功的收费调用。
- 暂停的周期性安排恢复后只执行未来计划，不补跑历史次数；具体暂停工作由用户明确选择继续。
- 用户自带模型账户或 API 密钥时，不收取该模型的 token 积分费用；实际使用的平台收费工具和计算资源仍计费。明细区分费用归属，归属无法确认的资源不开放收费执行。
- 套餐价格、积分包、资源单价与具体额度做成配置，正式开放购买前另行确认。演示配置明确标记为测试，生产缺少正式配置时禁止销售；访谈示例数字不作为正式售价。
- 退款结果不明或处理中继续冻结，只有渠道确认终止且未退款才解除冻结；超过 24 小时未确定转人工处理，仍展示退款处理中。
- 每个收费步骤预留时锁定单价。一次运行设积分消费上限，子代理及委派共享该上限；提高上限需用户明确确认，默认上限属于上线前配置。
- 订阅降级允许已开始的收费步骤结束，后续按基础额度安排，超额工作暂停或等待；积分余额不代替订阅资源权益。
- 分享、转移或修改任务不自动变更付费账户。原付费人停用账户或撤销授权后不启动新的收费步骤；接手者明确接受付费责任后才恢复。外部事件沿用事先授权的付费账户。
