# Astryx UI 迁移讨论

状态：各项决策已确认，等待整体方案确认后实施试点。

## 已确认（2026-11-16）

- 采用 Meta Astryx 组件和视觉体系，保留现有业务功能、页面入口和操作流程。
- 主要目标是视觉一致、减少自制基础组件；导航重组和业务流程改版另作决策。
- 先迁移一个包含真实表单、弹窗或列表的代表页面，验证视觉、交互和构建兼容性，再决定全面替换。
- 本次范围为 `app/` Web 前端；桌面端和移动端独立界面留待后续处理。
- 试点选择 Bots 列表及创建 Bot 流程。
- 试点期间保留旧界面用于回退；全面迁移成功后退出现有四套皮肤，统一使用 Astryx，保留明暗主题和品牌配置能力。
- 以 Astryx 默认设计规范为基础，适配 OpenBot 品牌色、标识和必要布局，不复刻旧皮肤。
- Astryx 基础组件优先；流式消息、代码展示、终端和浏览器画面等专用能力保留原实现，统一外围样式。
- 试点验收：Bots 列表与创建流程可用，权限和错误提示正确；明暗主题、窄屏布局正常；键盘可操作、弹窗焦点正确；类型检查、生产构建及实际浏览器检查通过。
- 试点通过技术检查后提供可运行界面和截图，等待用户确认视觉效果，才启动全面迁移。
- 全面迁移按功能分批验证：先应用框架和常规管理页面，再迁移 Conversation 等复杂交互。
- 所有调用迁走后再清理旧皮肤和无用依赖；不以移除整个 Tailwind/Base UI 技术栈作为独立成功标准。

## 实施前技术核查

- 核实 Astryx 版本、StyleX 构建接入与现有样式共存方式。
- 核实 Bots 列表及创建流程的组件边界，确定试点隔离与回退方式。
- 如发现技术阻碍会改变已确认范围或功能，回到设计讨论；一般实现细节由实施阶段处理。
