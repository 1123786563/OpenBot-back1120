Part of #61

Blocked by: #65, #67, #68, #13

## What to build

将套餐权益绑定实际并发和自动任务名额，订阅到期后保留数据并按基础额度运行。

## 实施边界与当前状态

只实现订阅权益约束；复用 #13 的恢复机制及 #37 的模型后台计费，不重做身份停用或任务调度系统。

## 阻塞关与解除条件

需可修改后端的调度/配额入口和真实身份。仅页面隐藏功能或配置计算正确不能通过。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 基础与订阅额度由已购买有效权益决定，不以积分余额是否大于零判断订阅是否有效；积分包不自动提高资源额度。
- [ ] 到期保留所有任务和数据，超基础名额任务暂停，由用户选择保留启用；不随机删除或悄悄执行超额任务。
- [ ] 降低并发时已开始收费步骤允许结算，后续调度遵守新额度；与停用要求冲突时身份安全停用优先，不用订阅规则延迟停用。
- [ ] 下一周期权益及积分仅到达生效时应用，重复调度/服务重启不重复发放；提前预购不改变当前权益。
- [ ] 充值、登录或服务恢复不自动续跑已暂停的具体工作，周期安排恢复只执行未来计划，不补跑历史次数。
- [ ] 用户手动恢复服务端重新检查身份、付款授权、余额和额度，重复恢复不启动重复Run。
- [ ] 通过真实后台任务及公开查询验证到期、恢复、预购、降级和并发边界，保存可控时间和执行证据。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
