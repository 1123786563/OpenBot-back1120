Part of #61

Blocked by: #62

## What to build

交付微信渠道可复用适配器，统一下单、核实交易、退款状态和账单下载。

## 实施边界与当前状态

合同完成后可独立推进官方协议与故障测试；不依赖真实商户开通，本票不实现订单履约。

## 阻塞关与解除条件

协议级可完成，真实微信收退款由商户闭环票验收；不得伪造真实成功证据。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 固定官方 API v3/SDK 版本，实现 Native/H5 下单、商户单号查单、关单、退款、查退款和交易账单下载合同。
- [ ] 按官方签名/验签和资源解密规则处理通知，验证时间/重放策略、公钥或证书轮换及未知key行为，签名失败不得返回已核实交易。
- [ ] 正确输出商户、应用、订单、金额币种、渠道交易及实际付款时间，供订单服务校验；不在适配器直接发积分。
- [ ] H5链接刷新与订单30分钟到期分离；明确外部手机浏览器限制和不支持环境引导，不把Native二维码长按当同手机通用支付。
- [ ] 退款受理、处理中、成功、明确失败和未知结果区分；重试复用 out_refund_no，超时不盲目重复创建退款。
- [ ] 交易账单按官方下载与完整性规则处理，失败可恢复且不记录密钥或完整敏感报文。
- [ ] 以官方签名向量/受控HTTP边界测试成功、验签失败、超时、乱序、重复、关单已支付及证书轮换；输出明确协议测试结果和真实联调未完成标记。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
