Part of #16

## What to build

选定一个模型与 Harness 组合，让测试工作从实际执行入口通过独立部署的 Bifrost 获得响应，并证明后端及账本具备后续逐次校验接入条件。

遵循父规格 #16 与已接受的 ADR 0004、ADR 0003；本票不扩大订阅迁移、BYOK 或自动重试范围。

## Acceptance criteria

- [ ] 核实可修改后端源码或受支持接口的访问和运行方式，记录可复现启动步骤；复用已有后端获取成果，不重复建立另一套后端。
- [ ] 锁定用于验证的 Bifrost 开源版本及一个明确的模型 × Harness 组合，说明选择依据、使用的协议及必要能力；不以所有组合兼容为前提。
- [ ] 使用测试凭据，从实际执行入口发起工作，经 Harness、Bifrost 到受控供应商，返回可见响应；记录实际供应商请求，证明调用确实经过网关。
- [ ] 验证账本接口能够表达付款账户、原始工作、逐步预留、锁定单价、实际结算、释放及幂等关联；列出已证实能力和缺口，不将模拟接口当作真实后端能力。
- [ ] 基于实验确定逐次校验放在网关扩展还是内部代理，证明所选路径可以阻止无有效预留的请求，并识别 SDK 内部调用和重试是否能够绕过。
- [ ] 记录调用、Run、用户、Bot、付款人与预留的关联契约，区分用户身份和付费归属；不在结果中暴露测试密钥。
- [ ] 形成可重复运行的最小验证及失败证据；正式积分、真实用户付费流量保持关闭。
- [ ] 只有可用后端及账本接口和接入方案均有验证证据时才完成本票。若接口缺失，记录具体阻断及解决条件并保持未完成，不能仅凭调研报告关闭本票并解锁第 2 票。

## Verification

优先经实际执行入口与供应商 HTTP 边界验证外部行为，核对用户可见状态和积分记录。复用现有 Harness 模型选择、provider-boundary 测试模式；实现票在本票范围内提供自动化行为验证，不以私有函数调用断言替代端到端结果。
