Blocked by: #67, #68, #71, #74, #77

## What to build

用户可在真实后端上查询账务、购买套餐/积分包、查看退款及周期调整。

## 实施边界与当前状态

只做计费 API/页面，复用既有登录与应用框架；不重新迁移Astryx或实现渠道协议。

## 阻塞关与解除条件

生产页面验收依赖真实身份和账务接口；设计/空页面可提前准备但不能关闭本票。真实商户三端闭环另在T18验收。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 新增源API合同并生成客户端，符合组织作用域、problem+json、幂等写入和cursor分页；内部预留/结算接口不暴露给浏览器。
- [ ] 显示可用、预留、冻结、过期/补偿、结算确认状态及六位积分，微小消费不显示为免费，人民币订单与积分消费明确分开。
- [ ] 支持月付套餐、续费/下期换档资格、未订阅积分包购买和最多预购一期；退款中对应购买不可绕过。
- [ ] 收银台显示渠道入口、订单有效期、支付确认中和异常；回跳后以服务端查询为准，不由浏览器标记已付。
- [ ] 消费明细可追溯Run/步骤、资源用量、锁定价格及费用归属，展示原周期快照和追加调整，不直接展示Lago账单为用户欠款。
- [ ] 退款申请及运营审核权限分离，用户只能查本人订单/退款，不能通过修改URL或请求字段跨账户操作。
- [ ] 用真实后端、测试渠道和实际页面流程验证购买→确认→余额→消费→退款/调整；正式商品或服务能力缺失时禁止生产销售。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
