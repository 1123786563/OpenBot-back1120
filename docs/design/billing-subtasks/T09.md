## What to build

交付支付宝电脑/手机网站支付、退款和账单适配器。

## 实施边界与当前状态

合同完成后可独立推进；不实现第二套订单/积分状态机，不迁移身份入口。

## 阻塞关与解除条件

官方协议与替身测试可完成，真实商户产品、付款及退款在商户闭环票完成。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 固定支付宝SDK及协议路线，核实 page.pay、wap.pay、query、close、refund、fastpay.refund.query 和 bill.downloadurl.query 或已核验等效接口，不混用弃用exec与未经核验v3路径。
- [ ] 服务端构造网页支付入口，notify验签及商户应用/订单字段保真，return_url只用于导航而非支付确认。
- [ ] 金额精确换算整数分，拒绝币种/金额/应用不匹配；输出实际交易状态和付款时间，不直接发放权益。
- [ ] 退款按原 out_request_no 去重，查询成功不等同退款成功；超时/未知结果交给订单退款状态机继续查询。
- [ ] 支持交易账单地址申请和下载/解析的适配合同，失败可重试且保留可核对交易身份。
- [ ] 在官方验签样例与受控HTTP边界测试重复/乱序通知、伪造签名、支付查询、关单竞争和退款未知，不使用生产密钥。
- [ ] 记录电脑/手机入口和当前产品限制，报告协议测试与真实商户联调的不同完成状态。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
