Part of #61

Blocked by: #64, #65

## What to build

交付可供 Bifrost 和其他执行者调用的真实账本预留、结算与释放服务。

## 实施边界与当前状态

可隔离实现，不依赖 Bifrost 转发完成；只提供账本语义，不重复 #33/#36/#38 的模型执行接入。

## 阻塞关与解除条件

依赖真实 PostgreSQL 核心和价格规则。未获得实际后端身份时只供受控测试入口调用；不得把该入口暴露为客户端任意扣分 API。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 预留时同时约束账户可用余额、有效批次及 root Run 剩余上限，先扣即将到期批次；两个并发各60争抢80仅一个成功。
- [ ] 锁定价格版本、调用/步骤及来源批次；父子工作共用同一上限的账本合同具备持久化约束，提高上限要求已验证的用户明确授权。
- [ ] 实际结算仅消费实际用量并释放余量；16路重复结算只有一笔流水与outbox，同键不同金额或付款归属拒绝。
- [ ] 旧周期100加积分包100，预留150后跨界消费120，旧周期扣100、积分包扣20且剩80；另测旧100预留80消费60后过期40，下一步不能花过期余额。
- [ ] 退款冻结与预留互斥，余额不足或无法可靠持久化时拒绝新增预留；不在持锁事务内等待模型/渠道网络。
- [ ] 未知用量24小时释放；到期释放与结算竞态不重复释放，释放后的迟到实际消耗记录为平台承担，不能追扣用户。
- [ ] 验证取消、明确未发送、用量已知和未知结果的不同结算结果；有效消耗计费，平台故障无效消耗可追溯补偿。
- [ ] 进程提交前后退出、重启、重投后余额与流水守恒，跨账户/跨Run预留复用被拒绝；导出供 #32 接入的真实测试服务与合同。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
