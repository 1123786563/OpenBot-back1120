Part of #61

Blocked by: #66

## What to build

将生产账本outbox可靠同步到Lago零金额计量，断网与重启不丢不重。

## 实施边界与当前状态

账本服务完成后可在当前仓库独立推进，无需后端源码或商户；不是另建积分权威。

## 阻塞关与解除条件

固定已验证社区版与PostgreSQL事件存储；真实outbox和持久化worker必需，不能仅用手动发事件脚本关闭。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 按稳定账户创建customer和持续计量关系，零固定费/零单价指标汇总资源与微积分；不依赖Premium时区或invoiceable=false。
- [ ] 资源用量和扣分事件分别上报，关联步骤与原始工作、费用承担方和原事件身份，不生成新的人民币应收。
- [ ] occurrence_us原始整数微秒与精确十进制timestamp一致，校验范围与内容；不传对话正文、输出、支付密钥。
- [ ] outbox租约/重试及发送状态持久化，发送后响应前崩溃再发不重复；重复422须核对错误码与原事件内容，语义冲突进入人工差异。
- [ ] Lago断网时本地可可靠记账仍可消费；本地记录失败必须拒绝新增消费；恢复后待发集合收敛。
- [ ] 同一调用多次通知、乱序资源/结算事件和平台承担迟到成本正确归属，记录发送水位与待处理项。
- [ ] 真实PostgreSQL+Lago完成断网、worker重启、并发投递和零价最终账单验证；不把API已接收等同聚合已完成。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
