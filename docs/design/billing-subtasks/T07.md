Part of #61

Blocked by: #64, #65

## What to build

在隔离账务服务内实现购买、续费和积分包订单的可恢复履约闭环。

## 实施边界与当前状态

可用受控支付适配器替身独立验收；真实个人身份与真实渠道分别由账户票和商户闭环票接入。

## 阻塞关与解除条件

依赖账本与商品规则；不以测试适配器通过宣称真实商户到账。正式销售需后续身份、渠道和总体验收关。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 订单保存账户、商品/价格版本、金额币种与30分钟到期时间，支付尝试与业务订单分离，重复创建幂等且冲突拒绝。
- [ ] 仅接受渠道适配器核实的商户/应用/订单/金额/币种匹配结果；前端回跳和未验签通知不能直接开通。
- [ ] 同一订单的并发/重复成功只发一次积分或权益；两渠道同时成功保留第二笔收款并转异常退款，不能重复履约。
- [ ] 支付确认与账本发放通过同事务或可恢复编排保证一致；在确认后/发放前及提交后响应前崩溃，重启补齐且不重复。
- [ ] 首次和过期重购以实际开通时间起算；续费最多一期、不提前发下期积分，退款中不能购买同一待生效周期。
- [ ] 本地订单到期先查单关单；付款发生在有效期内的迟到通知正常履约，失效后真实付款进入异常退款，不吞款。
- [ ] 订单公开状态区分待支付、支付确认、已支付/履约、关闭与异常，保存渠道交易证据；不把请求超时当付款失败。
- [ ] 测试未订阅可买积分包、订阅过期仍可使用、重复及乱序通知、关单竞争和服务重启；可从业务查询核对订单与积分。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
