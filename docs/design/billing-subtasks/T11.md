Part of #61

Blocked by: #63, #67, #68, #69, #70, #71

## What to build

在受控商户联调环境用真实受支持渠道确认付款、权益和退款的完整结果。

## 实施边界与当前状态

复用已完成适配器和订单/账本服务，不重新实现渠道协议或Casdoor。

## 阻塞关与解除条件

同时受后端身份与商户产品/凭据/公网回调阻塞。所有前置票完成且具备经授权受控交易条件才能执行；沙箱不具备能力时明确保留真实联调缺口。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 微信与支付宝分别通过真实支持的网页支付发起、渠道结果核实、订单履约和用户余额查询，保存脱敏交易证据。
- [ ] 主动查单覆盖通知缺失，回跳早于通知显示确认中，重复成功通知不重复发放。
- [ ] 分别完成退款请求、查询最终结果、资金状态核对和账本权益撤销，不能以受理响应代替完成。
- [ ] 验证公网通知验签与商户/应用/金额币种检查；测试环境可注入伪造、重复、乱序通知，不造成错误履约。
- [ ] 验证30分钟关单/迟到付款规则及多支付尝试异常处理；实际难以人为触发的渠道竞态辅以适配器测试并区分证据。
- [ ] 获取两渠道交易/退款账单，能按交易标识关联到本地订单和退款记录。
- [ ] 服务重启后已支付未发权益能恢复；环境矩阵、回调/密钥配置名称和限制记录完整，无密钥公开。
- [ ] 本票仅受控联调，不授权直接向所有用户开放收费；正式开关等待总体验收。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
