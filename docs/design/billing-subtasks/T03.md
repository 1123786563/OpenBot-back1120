## What to build

在当前仓库建立可持久化、可恢复的账本核心，支持幂等入账和可查询的批次余额。

## 实施边界与当前状态

前置合同完成后可独立推进，不等待后端源码或商户；使用隔离内部测试入口，正式身份挂载由账户接入票完成。

## 阻塞关与解除条件

本票完成要求真实 PostgreSQL，不接受 SQLite 参考模型或内存余额。生产挂载未完成不妨碍隔离核心验收，但不能对真实用户开放。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 通过迁移建立账户、积分批次、不可覆盖流水、幂等记录、调整及待发送 outbox；账户和业务身份唯一约束落到数据库。
- [ ] 套餐、积分包、补偿批次分别保留来源和到期时间；仅接受授权内部测试/服务入口入账，不提供用户任意加分接口。
- [ ] 同业务键同内容重试返回原结果，同键不同账户/金额/周期拒绝；入账和 outbox 在同一事务提交。
- [ ] 至少两个账户的余额与明细隔离，错误账户访问被拒绝；查询可验证批次原值、可用、预留、已消费、冻结/过期的守恒定义。
- [ ] 追加调整以账户、原事件、类型唯一，内容不可覆盖；16路同键重试仅一条调整及一个 outbox，重启后重试仍不新增。
- [ ] 在提交前、提交后响应前故障退出并重启，验证无半笔流水、无丢失待发送记录、无重复发放；使用真实数据库连接而非私有函数计数。
- [ ] 交付可重复初始化和升级的隔离迁移、内部业务入口及查询证据；不把 outbox 已写入等同于 Lago 已收到。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
