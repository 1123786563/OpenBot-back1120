Part of #61

Blocked by: 无任务前置

## What to build

交付账户、积分、订单、渠道和用量的可执行合同，使后续模块共享一套业务语义。

## 实施边界与当前状态

可在当前仓库立即推进；只定义和验证合同，不获取第二份后端，不实现 Bifrost 转发或 Casdoor 登录。

## 阻塞关与解除条件

无任务前置。无需商户密钥或匹配后端即可完成本票；合同通过不代表真实后端已经实现。

## Acceptance criteria

- [ ] 定义 Billing Account、Credit Lot、Reservation、Settlement、Adjustment、Order、PaymentAttempt、Refund、Metering Relationship 的稳定身份、必需字段和可观察状态；区分个人身份、付款账户及组织作用域。
- [ ] 明确 reserve/settle/release/adjust、购买/查单/退款的请求结果、幂等键作用域、同键不同内容冲突、授权主体和错误合同；声明这些是拟新增接口而非镜像已有能力。
- [ ] 明确整数微积分、整数人民币分、六位舍入、精确时间、价格版本、root Run 上限及未知用量24小时规则；序列化无浮点损失并拒绝超范围输入。
- [ ] 公开业务 API 遵循组织作用域、problem+json、写入幂等键和 cursor/limit；内部结算接口不开放给浏览器；渠道回调不依赖用户 session。
- [ ] 建立隔离 PostgreSQL/Lago 测试环境合同和唯一支付适配器替身边界；测试凭据、数据、清理流程可复现且不触碰现有数据库。
- [ ] 将合同与 #32/#33 的模型调用归属及预留需求核对，记录衔接点；本票不等待 #32 关闭，不产生循环依赖，也不实现网关校验。
- [ ] 源合同生成客户端及 lint/check 通过，错误、金额和幂等示例可由自动化检查；不得手改生成文件或以空 schema 完成。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
