Part of #61

Blocked by: #64, #4, #7

## What to build

让真实登录用户只能访问自己的计费账户，并让服务端为执行签发可信付款上下文。

## 实施边界与当前状态

复用 Casdoor #2/#3/#4/#7 的源码、身份和空间成果；本票只绑定账务，不重做登录、个人空间初始化或邮箱变更。

## 阻塞关与解除条件

后端源码关：必须有与部署匹配的可构建后端或等效受支持扩展，且依赖票已验收。历史基线可读不算当前镜像匹配；模拟身份只能准备测试不能关闭。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 由服务端稳定身份和 Personal Workspace 解析唯一 Billing Account，并发登录/重复初始化不新建多个账户。
- [ ] 邮箱变更仍对应同一账本，不能用同邮箱合并不同身份；不得以 default 组织或部署 actor 当个人付款人。
- [ ] 两用户跨账户读余额、订单、退款、明细与写操作均拒绝，查询合同中的组织作用域实际生效。
- [ ] 公开购买查询与可信服务内部预留结算权限分离，浏览器不能伪造 personId/payerId/root Run 或直接加减积分。
- [ ] 提供账户有效性/付款授权查询和可验证的归属上下文，给 #32/#37/#38 及非模型执行接入使用；本票不重复网关转发和委派执行。
- [ ] 复用现有用户停用状态而非建立第二套身份源，错误或无身份时失败关闭；保留既有审批和能力授权边界。
- [ ] 通过真实登录与公开业务 API 验证持久化账户、归属、权限和重启，不以静态token或模型mock替代后端验收。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
