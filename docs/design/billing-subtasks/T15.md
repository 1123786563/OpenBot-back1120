Part of #61

Blocked by: #66, #67, #18, #11, #12

## What to build

让非模型的收费工具和计算资源在实际执行前预留、完成后结算。

## 实施边界与当前状态

仅覆盖模型网关之外的资源；模型、辅助模型及委派模型执行继续由 #32–#39 负责，不重复实现。

## 阻塞关与解除条件

后端源码关：复用 #18 的真实工具/审批链和 #2 的服务端基线，并满足身份停用/失联约束。没有执行前不可绕过钩子则保持阻塞；仅Harness客户端加余额检查不能关闭。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 盘点首期实际收费的工具/计算资源及收费单位，逐项记录执行入口、最大成本、费用承担方和可用量证据；不能证明成本上限者保持关闭。
- [ ] 在既有鉴权、Bot Grant和Approval完成后、真实资源动作前校验付款人/root Run并预留；不在等待用户审批时长期冻结积分。
- [ ] 成功、取消、断流、未知执行结果和平台故障分别按账本规则结算，不能因调用错误假定免费或自动重做结果未知写操作。
- [ ] 并发工具/计算步骤与模型步骤共享账户及root Run预算，不额外创建子预算绕过上限；复用T05接口。
- [ ] 停用/撤销/身份状态失效后不能新开收费步骤，已经发生的资源消耗保留结算依据；复用 #11/#12 状态，不重做Casdoor通知机制。
- [ ] 测试真实执行入口、工具提供方边界和账本结果，伪造账户/复用他人预留、直达资源、余额不足及账本故障均不能绕过。
- [ ] 本票按明确清单逐项给出可开放/关闭状态，不以一个示例工具通过宣称全部资源覆盖。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
