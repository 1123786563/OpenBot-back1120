Part of #61

Blocked by: #66, #68

## What to build

使未使用购买可人工退款，冻结、撤销和补偿在重试与并发下保持账务一致。

## 实施边界与当前状态

账本/订单完成后可用渠道替身独立验收，真实退款在商户闭环票验证。

## 阻塞关与解除条件

必须先具备原子预留/冻结与订单履约；权限受控的内部审核入口可测试，生产使用依赖真实身份接入。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 审核仅允许未使用积分包、未开始续费周期常规全额退款；已消费/已开始不提供常规自助退款，异常收款与平台故障单独标原因。
- [ ] 审核动作记录操作者、对象、原因及原交易；冻结对应批次或待生效权益与消费预留原子互斥，审核不能冻结他人账户。
- [ ] 渠道确认退款成功才撤销，明确终止且未退款才解冻；未知/处理中继续冻结并查单，超过24小时转人工而非自动解冻。
- [ ] 解冻后遵守原到期时间，已过期积分不能恢复为可花余额；退款与到期、消费、重复审核并发保持守恒。
- [ ] 退款重试使用原渠道退款标识；重复成功通知只撤销一次，退款请求超时后不重复退钱。
- [ ] 换档原续费退款完成前禁止新购同周期；成功后可买新档，失败后原权益状态恢复但不提前发积分。
- [ ] 平台故障恢复原扣减来源，来源套餐已过期则发到账后30天有效补偿，关联原消费且重复补偿幂等。
- [ ] 使用真实PostgreSQL、可控时间和支付边界替身覆盖冻结竞态、进程中断、未知结果恢复及原批次核对，用户可查询处理状态。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
