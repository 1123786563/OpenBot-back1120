Blocked by: #73, #65

## What to build

按事件重建用户周期，可靠处理UTC账单差异、并发补传和微秒边界。

## 实施边界与当前状态

可独立于商户和OpenBot镜像测试；复用账本调整操作，不新建另一套余额或价格复算。

## 阻塞关与解除条件

依赖真实同步worker与周期规则。持续高负载/ClickHouse不在首期承诺内，但生产PostgreSQL重扫和断点恢复必须通过。

只有上述前置任务验收完成后才进入本票正式实施；可以提前阅读和准备夹具，但不能用提前准备关闭本票。

## Acceptance criteria

- [ ] 固定本地持久化序号水位K及预期ID/内容集合，读取全部分页；扫描中插入导致重复/漏读时通过重扫去重核对集合，不以两次总额相同判完成。
- [ ] UTC粗筛适当扩窗，按可信occurrence_us做[start,end)整数过滤；缺失/冲突时间进入差异，不能用毫秒序列化timestamp静默替代。
- [ ] 验证闰年及普通年月末、交界前后1微秒、分页移动、跨K新事件、未知/缺失事件和重启续扫。
- [ ] Lago已出UTC二月账单15、原事件迟到后32的场景，原周期追加17调整，不覆盖快照、不再次扣积分。
- [ ] 迟到事件重新打开受影响旧周期，账户+原事件+调整类型唯一，重复扫描/重投只一条调整；不同内容报冲突并保留原记录。
- [ ] 资源量、用户微积分、平台承担和用户自付分别核对；来源批次周期与发生时间周期分开，不把跨界预留结算认作错误。
- [ ] 差异查询提供扫描水位、未确认发送、缺失ID和处理原因，只有截至该水位对齐才标完成，历史窗口仍允许后来调整。
- [ ] 通过业务查询与真实Lago/PostgreSQL演示完整流程，不以既有Python样例运行代替生产worker验收。

## 测试边界与完成要求

遵循父规格 #61 与 ADR 0003/0004，保持 Lago 社区版、OpenBot 北京时间周期及唯一积分账本。优先从受信业务 API/用户行为验证，使用真实 PostgreSQL/Lago；支付协议票在外部适配器边界使用替身，真实商户结果由专门闭环票验证。参考模型或静态调研不能替代本票要求的生产模块/集成证据。

完成时附可重复命令或操作步骤、版本、期望/实际结果、故障场景和未验证范围；不得包含凭据。`ready-for-agent` 仅表示任务已说明清楚，不表示依赖或外部条件已解除。
