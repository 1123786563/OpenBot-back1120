# OpenBot Web 浏览器端到端测试

OpenBot Web 采用 `e2e-inc/e2e` 和 Chromium 验证从界面到服务端的用户流程。Web 测试按行为逐步迁移，旧用例在对应覆盖得到验证后再移除。服务端测试和现有 HTTP smoke 继续使用 `bun:test`。

首批验证访客跳转、Casdoor 登录、Bot 创建与持久化、聊天流式回复与持久化。PR 使用固定的流式模型回复和代码断言。有 Casdoor 测试凭据的受信任任务运行登录后用例，fork PR 运行访客用例，以及独立单用户环境中的团队版导航和个人版用例。真实模型通过手动任务验收。

稳定的交互通过浏览器 API 执行。无法稳定脚本化的交互由 `agent.act()` 执行。每次代理操作都必须有后续代码断言，验证预期的可见状态、提交的请求或刷新后保留的数据。手动模型验收也使用代码检查回复。OpenBot 回复使用的产品模型与执行代理步骤的测试模型分别配置。
