# Casdoor 统一用户身份与登录

Casdoor 负责 OpenBot 用户身份与统一登录，通过现有 OIDC 身份提供方接口接入；OpenBot 继续管理应用会话与业务权限。该边界将统一身份与业务授权分开，优先复用已有接入能力，具体兼容性仍需验证。

范围覆盖 Web、手机端和桌面端，不采用仅先接入 Web 的范围；无需迁移或保留历史用户数据。此决定不构成删除现有数据的操作授权。

所有普通用户必须通过 Casdoor 登录，关闭其他普通用户登录入口和免登录模式。获得 Casdoor 中 OpenBot 应用访问资格的用户首次登录时，自动创建 OpenBot 用户；用户对平台是普通用户，对自己的个人工作空间是所有者。平台管理权限由 OpenBot 单独授予。

产品面向用户提供 SaaS。每位新用户默认拥有独立个人工作空间，Bot、对话和连接与其他用户隔离，首期不支持邀请其他用户加入。允许任何人通过 Casdoor 自助注册，完成邮箱验证后即可进入 OpenBot，无需管理员审批。

个人工作空间映射到首次登录时自动创建的专属组织，重复登录不重复创建。用户拥有自己空间的管理权，没有平台管理权。不同用户的 Bot 计算机必须隔离，包括文件、浏览器登录状态和凭据；同一用户的 Bot 可以共享自己的计算机。

桌面端改为连接云端 SaaS，与 Web、手机端访问同一账户和个人工作空间，不再默认启动本地独立服务。

普通退出只退出当前客户端，不停止云端任务；另提供退出所有设备以撤销全部 OpenBot 登录会话。

在 Casdoor 停用用户后，OpenBot 必须在一分钟内阻断所有客户端访问，并停止该用户的后台任务和 Bot 计算机；保留数据以便恢复。这是产品要求，现有接口能否支持仍待验证。

邮箱是可变联系方式，不作为账户归属的唯一依据。修改邮箱保留同一个 OpenBot 用户与个人工作空间，新邮箱需要重新验证。

平台管理员也统一通过 Casdoor 登录，不保留公开的备用密码登录入口。Casdoor 故障时通过服务器运维恢复，上线前必须验证恢复流程。

如果账户状态超过一分钟无法确认，暂停用户访问和后台执行，身份服务恢复后才允许访问。此选择优先保证停用时限，接受 Casdoor 故障影响已登录用户及其后台执行的可用性代价。

首期不提供用户自助永久注销，仅支持管理员停用并保留数据。

账户解除停用或身份服务恢复且账户状态验证通过后，只恢复访问资格。已经停止的任务与 Bot 计算机由用户手动恢复，不自动重启，以免恢复身份服务时意外重新触发外部操作。

整体设计已由用户确认，作为后续实现与验收依据。现有 OIDC 接口是否足以承接公开注册及个人组织初始化仍需验证，不能将现有企业 SSO 接口视为已经满足 SaaS 要求。

## 实现前验证条件

- 当前仓库使用已发布的服务端镜像，缺少认证服务端实现。需要确认可修改的服务端源码或所用镜像的扩展能力。
- 验证现有按邮箱域名路由的企业 SSO 能否支持公开注册与统一 Casdoor 入口。
- 验证三端身份关联、邮箱变更、组织初始化的并发及失败重试，避免重复用户或空间。
- 验证服务端跨组织访问、文件、连接凭据及 Bot 计算机隔离，不能仅凭前端隐藏入口认定隔离成立。
- 验证停用通知、状态检查失败、会话撤销、任务及计算机停止共同满足一分钟要求；只撤销 Casdoor 令牌不足以证明 OpenBot 已停止执行。

Casdoor 官方文档描述了 [OIDC 接入](https://casdoor.ai/docs/how-to-connect/oidc-client/)、[用户停用时撤销令牌与会话并发送退出通知](https://casdoor.ai/docs/user/overview/)和 [Webhook](https://casdoor.ai/docs/webhooks/overview/)。这些是候选机制，不代表当前 OpenBot 镜像或实际部署的 Casdoor 版本已经支持上述端到端要求。
