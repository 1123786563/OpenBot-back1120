# OpenObserve 统一日志查询，保留 Opik 与业务审计记录

为统一运行日志和审计日志的查询入口，采用自托管 OpenObserve，保留 Opik 承担 Agent 执行轨迹与模型调用观测。保留 Activity 页面和 PostgreSQL 审计记录，OpenObserve 中的审计数据是供查询的副本，不替代业务审计权威记录。

这一划分接受维护两个观测系统的成本，避免重复建设 Agent 观测功能，也避免日志平台的保留策略或故障改变业务审计记录。模型网关日志继续遵守 ADR 0004 默认不记录请求及响应正文的约束。

首期只采集服务端运行日志与审计日志，不自动上传桌面端和 CLI 本地日志。OpenObserve 仅供平台管理员访问；运行日志保留 30 天，审计副本保留 90 天，PostgreSQL 原有审计保留规则不变。

OpenObserve 不可用时不阻断业务，采集端采用有限缓存与重试，超过容量或重试限额后允许丢弃导出副本；PostgreSQL 审计记录继续正常保存。因此集中查询允许存在缺口，不承诺导出副本完整无损。

日志只采集必要字段：时间、服务、环境、级别、错误信息，以及适用的请求 ID 和 Run ID；无关联 Run 的系统日志不强行添加 Run ID。上传前去除凭据，不采集对话正文、模型输入输出、工具参数与返回正文；错误信息也必须遵守这些限制。Agent 详细执行内容继续在 Opik 查看。

从接入时开始收集新日志，不回灌历史运行日志或 PostgreSQL 历史审计记录，历史审计仍可通过 Activity 查询。告警规则与定制仪表盘不在首期范围内。

## 验收标准

- OpenObserve 能查询新产生的服务错误与审计事件。
- 含 Run ID 的日志能关联到同一次 Agent 运行。
- 仅平台管理员可访问，运行日志 30 天和审计副本 90 天的保留策略生效。
- 停止 OpenObserve 后，业务与 PostgreSQL 审计写入正常；恢复后新日志继续入库。
- 检查采集结果，确认凭据与上述正文内容未被上传。

以上分项决策已确认，整体方案待最终确认后进入实施；此记录不代表接入已经实现或通过验收。具体部署版本、采集链路、缓存容量与重试参数属于实施时需要验证和记录的技术细节。
